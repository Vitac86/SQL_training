# sql_trader_starter

Учебный проект для изучения SQL, SQLite, проектирования реляционных БД, работы с SQLite из
Python, pandas и импорта финансовых данных — на примере учебной торговой базы данных.

Это не production-система. Цель — обучение с нуля/начального уровня, с упором на финансовые
и торговые данные: инструменты, тикеры, счета, сделки, BUY/SELL, цены, объёмы, оборот,
ликвидность.

## Быстрый старт

### 0. Окружение (проверено при создании проекта)

| Инструмент | Версия |
|---|---|
| Python | 3.11.0 (см. примечание про несколько установленных Python ниже) |
| SQLite CLI (`sqlite3.exe`) | 3.53.4 |
| Node.js | v24.14.0 |
| npm | 11.9.0 |
| VS Code | 1.132.1 |

**Важное примечание про Python.** На этом компьютере команда `python` в PATH может указывать
не на тот Python, который нужен для работы (в частности, был обнаружен `python`, привязанный
к среде Inkscape, без `pip`). Поэтому для этого проекта создано отдельное виртуальное
окружение `.venv` на основе Python 3.11 — используйте именно его (см. ниже), чтобы не
зависеть от того, куда именно указывает `python` в системном PATH.

### 1. Виртуальное окружение и зависимости

```cmd
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

После `activate` команды `python` и `pip` в этом терминале будут указывать именно на
`.venv`, независимо от того, что стоит в системном PATH. Зависимостей всего две:
`pandas` и `openpyxl` (см. `requirements.txt`) — ничего лишнего (без SQLAlchemy, ORM,
серверных СУБД, веб-фреймворков).

### 2. Создать базу данных

```cmd
python 01_create_database.py
```

Скрипт полностью пересоздаёт `trading_training.db` из CSV-файлов в `data/`. Запускать можно
сколько угодно раз — например, если вы что-то случайно испортили в базе во время уроков.

### 3. Дальше — на выбор: sqlite3.exe или VS Code

---

## Способ A — sqlite3.exe (консоль)

Официальный консольный клиент SQLite. Это основной инструмент для урока 0 — там база
создаётся полностью вручную, без Python и без VS Code.

```cmd
sqlite3 trading_training.db
```

Полезные команды в начале сессии:

```sql
.headers on
.mode column
```

Другие полезные команды:

```sql
.tables              -- список таблиц
.schema имя_таблицы  -- структура конкретной таблицы (ключи, ограничения)
.schema              -- структура всей базы
.databases           -- какой файл базы сейчас подключён
.quit                -- выход
```

Важно: `.tables`, `.schema`, `.databases`, `.quit` — это команды именно консоли `sqlite3`
(dot-commands), не SQL. Они не требуют `;` на конце и не работают в других SQL-клиентах.
Обычный SQL (`SELECT`, `INSERT` и т.д.) всегда заканчивается `;`.

## Способ B — VS Code + SQLTools

Поскольку Node.js уже установлен, это предпочтительный GUI-вариант для повседневной
практики после урока 0.

Установлено и проверено в этом окружении:

- `mtxr.sqltools` (SQLTools) — версия 0.28.6
- `mtxr.sqltools-driver-sqlite` (драйвер SQLite для SQLTools) — версия 0.5.4

### Как подключить базу

1. Откройте папку `sql_trader_starter` в VS Code (`File -> Open Folder...`).
2. Откройте боковую панель SQLTools — иконка с изображением базы данных/розетки на левой
   Activity Bar (или через палитру команд: `Ctrl+Shift+P` -> "SQLTools: Focus on SQLTools View").
3. Настройки подключения уже созданы в `.vscode/settings.json` (см. ниже) — подключение
   называется **"Trading Training DB"** и указывает на `trading_training.db` в этой же
   папке через относительный путь, так что оно будет работать на любом компьютере, где
   склонирован этот репозиторий, без правки путей.
4. В панели SQLTools найдите соединение **"Trading Training DB"** и нажмите на него (или на
   значок подключения рядом), чтобы подключиться. Если это первое использование драйвера
   SQLite, расширение может предложить доустановить внутренний драйвер — согласитесь.
5. После подключения в дереве появятся таблицы базы (`instruments`, `accounts`, `trades`,
   `daily_prices`, `liquidity`) — можно раскрыть каждую и увидеть колонки.

### Как выполнять запросы

- Откройте `practice.sql` (это ваш рабочий файл для собственных запросов) или любой другой
  `.sql` файл проекта.
- Убедитесь, что в статус-баре внизу VS Code выбрано соединение **"Trading Training DB"**
  как активное (SQLTools показывает текущее активное подключение внизу окна).
- Выделите один SQL-запрос (или поставьте курсор внутри него, если запрос один и не
  разделён точкой с запятой на несколько) и выполните его: через палитру команд
  `Ctrl+Shift+P` -> "SQLTools: Run Query", либо горячей клавишей, которую покажет та же
  палитра команд (в разных версиях SQLTools это может быть `Ctrl+E Ctrl+E` — если
  комбинация не сработает, используйте палитру команд как надёжный способ).
- Результат появится в отдельной панели результатов SQLTools снизу/сбоку, в виде таблицы.

Если что-то в интерфейсе выглядит иначе, чем описано — ориентируйтесь на палитру команд
(`Ctrl+Shift+P`) и ищите там команды, начинающиеся с "SQLTools:". Интерфейс расширений
меняется от версии к версии, а команды в палитре остаются надёжным способом добраться до
нужного действия.

### Ограничение

Проект **не зависит** от SQLTools — вся база данных полностью работает и без VS Code, через
`sqlite3 trading_training.db` (Способ A). SQLTools — это просто более удобный интерфейс для
повседневной практики.

## Данные

Все данные учебные (синтетические), но структурно правдоподобные: реальные тикеры
Московской биржи (`SBER`, `GAZP`, `LKOH`, `ROSN`, `GMKN`, `MOEX`, `MTSS`), индикатор
денежного рынка (`RUSFAR`), валютные инструменты (`USD000UTSTOM`, `CNYRUB_TOM`),
гособлигация (`SU26238`) и один инструмент без единой сделки (`TEST0`) — специально для
разбора `LEFT JOIN`. Аналогично среди счетов есть один без единой сделки
(`ACC-DORMANT`).

Ориентировочные объёмы: 12 инструментов, 6 счетов, ~230 сделок, ~430 дневных цен, ~430
наблюдений ликвидности.

## С чего начать

1. Прочитайте этот README целиком (уже сделали).
2. Откройте `lessons/00_создание_базы_и_ключи.md` и пройдите урок 0 целиком, создавая
   `lesson_00.db` самостоятельно командой `sqlite3 lesson_00.db` — не открывайте готовую
   `trading_training.db` на этом этапе.
3. Не подглядывайте в `lessons/answers/00_answers.md`, пока не попробуете задания урока 0
   сами.
4. После урока 0 переходите к урокам 1-4 в том же порядке, работая уже с
   `trading_training.db`.
5. Параллельно или после уроков — `exercises.sql` для дополнительной практики и
   `practice.sql` как черновик для собственных запросов.
