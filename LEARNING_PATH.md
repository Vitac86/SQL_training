# Последовательный маршрут SQL Server / SSMS

Главный принцип: **мы не используем незнакомую конструкцию как объяснение другой незнакомой конструкции**. Сначала учимся читать данные, затем понимать структуру, потом создавать таблицы, после — считать, объединять, менять и администрировать.

Рабочий ритм: прочитай объяснение → **до выполнения** предположи результат → выполни запрос в SSMS → сравни → измени одну часть → выполни задания. Ответы к дополнительному практикуму — в `answers.sql`.

## Этап I. Увидеть и понять данные

- **[00. Первое знакомство с БД и SSMS](lessons/00_первое_знакомство.md)** — что такое таблица, SQL Server и SSMS; Object Explorer; New Query, F5, Results/Messages; SELECT.
- **[01. SELECT и сортировка](lessons/01_select_и_сортировка.md)** — SELECT *, отдельные столбцы, TOP, ORDER BY, AS, DISTINCT, вычисляемые выражения.
- **[02. WHERE и NULL](lessons/02_where_и_null.md)** — условия, AND/OR, IN, BETWEEN, LIKE, проверка отсутствующих значений.
- **[03. Типы данных](lessons/03_типы_данных.md)** — INT, BIGINT, VARCHAR, NVARCHAR, DECIMAL, DATE, NOT NULL; как увидеть типы через Columns в SSMS.
- **[04. Ключи и связи](lessons/04_ключи_и_связи.md)** — PK, FK, 1:N, справочники; Keys в Object Explorer. Пока сопоставляем записи вручную.
- **[05. CREATE TABLE и CHECK](lessons/05_создание_таблицы_и_check.md)** — **собственными руками** создаём таблицу, задаём CHECK/NOT NULL/PK, пробуем правильный и неправильный INSERT и видим ошибку. Ищем созданные ограничения в SSMS и в исходной схеме `dbo.trades`.

**Рубеж:** можешь объяснить, откуда взялось правило `quantity > 0`, показать его в схеме и понять ошибку INSERT без TRY/CATCH.
