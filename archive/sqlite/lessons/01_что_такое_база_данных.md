# Урок 1. Устройство готовой базы trading_training.db

## 1. От lesson_00.db к trading_training.db: меняем инструмент

В уроке 0 вы своими руками, через `sqlite3.exe`, собрали `lesson_00.db` и разобрали на
практике: `CREATE TABLE`, типы данных, `PRIMARY KEY`, `UNIQUE`, `FOREIGN KEY`, `CHECK`,
`NOT NULL`, `DEFAULT`, `INSERT`/`UPDATE`/`DELETE`, `ALTER TABLE`/`DROP TABLE`, транзакции,
`rowid`, базовую идею индексов, нормализацию и составные ключи. Всё это в этом уроке заново
подробно не объясняется — оно уже ваше.

Теперь меняются сразу две вещи.

**Меняется база.** Вместо маленькой базы, которую вы построили с нуля, — готовая
`trading_training.db`. Она уже собрана из CSV-файлов в `data/` скриптом
`01_create_database.py` и содержит правдоподобный набор торговых данных: инструменты, счета,
сделки, дневные цены, ликвидность. Схему этой базы вы не создавали — вы будете её
**исследовать**, как это обычно и происходит в реальной работе, когда вам дают доступ к чужой
базе.

**Меняется инструмент.** Основной рабочий интерфейс с этого урока — не `sqlite3.exe`, а
**VS Code + SQLTools**. `sqlite3.exe` никуда не пропал и остаётся полезным диагностическим
инструментом (например, чтобы быстро проверить что-то в терминале или пересобрать базу), но
обычные учебные запросы дальше по курсу вы выполняете через SQLTools.

Если базу нужно пересобрать с нуля (например, вы что-то случайно испортили в упражнениях):

```cmd
python 01_create_database.py
```

Это безопасно — скрипт полностью удаляет старый файл базы и создаёт его заново из CSV.

## 2. Новый рабочий процесс

```text
VS Code
   ↓
practice.sql
   ↓
SQLTools
   ↓
trading_training.db
   ↓
Query Results
```

Разберём каждое звено — это разные вещи, и их легко перепутать, когда видишь всё это первый
раз:

- **`practice.sql`** — обычный текстовый файл. Сам по себе он ничего не выполняет и ничего не
  «знает» о базе данных — это просто текст с SQL-командами, которые вы написали.
- **`trading_training.db`** — настоящий файл SQLite-базы на диске. Именно в нём физически
  хранятся таблицы и строки: инструменты, счета, сделки.
- **SQLTools** — расширение VS Code, клиент. Он берёт текст запроса из `practice.sql` (или
  любого `.sql`-файла), отправляет его в `trading_training.db` через настроенное соединение и
  получает ответ.
- **Query Results** — результат ровно одного выполненного запроса. Это **не** сохранённая
  таблица и не файл на диске — это временное отображение того, что вернул именно этот
  `SELECT`. Закроете вкладку с результатом — он исчезнет; сами данные в `trading_training.db`
  при этом никуда не денутся (если запрос их не изменял).

Из этого следует важная практическая вещь: пока вы просто **пишете** текст в `practice.sql`,
с базой ничего не происходит. Написать `DROP TABLE trades;` в файле — это просто буквы на
экране. Реально что-то случится с `trading_training.db` только в момент, когда вы явно
скомандуете SQLTools выполнить именно эту команду.

## 3. Проверяем подключение в SQLTools

Прежде чем писать что-то новое, убедимся, что связка VS Code + SQLTools +
`trading_training.db` действительно работает у вас. Шаги ниже проверены для версий,
установленных в этом окружении: SQLTools `0.28.6` и драйвер SQLite `0.5.4` (те же версии
указаны в `README.md`). Если у вас со временем окажутся другие версии — общая логика останется
той же, но конкретные пункты меню могут немного отличаться; в таком случае ориентируйтесь на
палитру команд (`Ctrl+Shift+P`) и ищите там всё, что начинается на «SQLTools».

1. Откройте в VS Code **всю папку проекта** целиком: `File → Open Folder...` →
   `sql_trader_starter`. Это важно: открыть нужно именно папку, а не отдельный файл — иначе
   VS Code не увидит `.vscode/settings.json` с настройкой подключения.
2. На левой Activity Bar найдите иконку **SQLTools** и откройте её. В панели будет три
   раздела: `Connections`, `Bookmarks`, `Query History`.
3. В разделе `Connections` уже должно быть одно соединение — **`Trading Training DB`**. Оно
   заранее настроено в `.vscode/settings.json` этого проекта:

   ```json
   {
       "sqltools.connections": [
           {
               "name": "Trading Training DB",
               "driver": "SQLite",
               "database": "${workspaceFolder}/trading_training.db"
           }
       ],
       "sqltools.useNodeRuntime": true
   }
   ```

   `${workspaceFolder}` — переменная VS Code, которая подставляет путь к открытой папке
   проекта. Поэтому соединение работает у любого, кто склонировал репозиторий, без правки
   путей вручную. `sqltools.useNodeRuntime: true` говорит SQLTools использовать уже
   установленный на компьютере Node.js — специально настраивать для этого ничего не нужно.
4. Нажмите на `Trading Training DB` в списке соединений (или на значок подключения рядом с
   ним), либо выполните через палитру команд (`Ctrl+Shift+P`) команду **`SQLTools: Connect`**.
5. После подключения под `Trading Training DB` появится дерево из пяти таблиц: `accounts`,
   `daily_prices`, `instruments`, `liquidity`, `trades`. Если вы видите этот список — соединение
   работает, можно двигаться дальше.
6. Откройте файл `practice.sql` в корне проекта.
7. Найдите в нём запрос:

   ```sql
   SELECT *
   FROM instruments;
   ```

8. Выполните его одним из двух способов:
   - выделите текст запроса целиком и нажмите `Ctrl+E Ctrl+E`;
   - либо, ничего не выделяя, просто поставьте курсор внутри запроса и через палитру команд
     (`Ctrl+Shift+P`) выполните **`SQLTools Connection: Run Current Query`** — этот способ
     срабатывает без выделения текста и не зависит от горячих клавиш, поэтому он надёжнее,
     если что-то пошло не так.
9. Откроется новая вкладка с результатом — это и есть **Query Results**. Вы должны увидеть
   таблицу из 12 строк: `SBER`, `GAZP`, `LKOH` и так далее.

Если вкладка с результатом не появилась или показывает ошибку — проверьте шаг 4: соединение
должно быть активным (обычно активное соединение подсвечено в статус-баре внизу окна VS Code).

## 5. Первый диагностический SQL-запрос

```sql
SELECT sqlite_version();
```

Это обычный SQL-запрос, а не что-то особенное — SQLTools отправляет его в базу точно так же,
как любой другой `SELECT`. Результат — одна строка с одной колонкой: версия движка SQLite,
который использует именно ваше текущее соединение. Число может отличаться от версии
`sqlite3.exe`, которую вы видели в уроке 0 — это нормально: SQLTools использует свой
собственный драйвер SQLite, независимый от системной консольной утилиты.

Теперь — важное отличие от урока 0. Там вы пользовались командами вроде:

```text
.tables
.schema
.headers on
.mode column
```

Это были **точечные команды (dot-commands) консоли `sqlite3.exe`**, а не SQL. Они не требовали
`;` на конце и работали только в этой конкретной программе. В SQLTools таких команд нет — в
поле запроса работает только обычный SQL. Там, где раньше был короткий ярлык вроде `.tables`,
теперь есть равноценный SQL-запрос — см. следующий раздел.

## 6. Список таблиц через SQL

```sql
SELECT
    name,
    type
FROM sqlite_schema
WHERE type = 'table'
ORDER BY name;
```

`WHERE` и `ORDER BY` вы подробно разберёте в уроке 2 — здесь достаточно воспринимать их как
готовый рецепт: «оставить только строки с `type = 'table'`» и «отсортировать по имени».
Запоминать синтаксис прямо сейчас не нужно.

`sqlite_schema` — специальная системная таблица, которую сама SQLite ведёт автоматически: в
ней перечислены все таблицы, индексы и другие объекты базы. По сути это SQL-версия того, что
в уроке 0 показывали `.tables`/`.schema` — только теперь это обычный `SELECT`, который
одинаково сработает в любом SQL-клиенте, а не только в `sqlite3.exe`.

Выполните запрос — вы должны получить 5 строк: `accounts`, `daily_prices`, `instruments`,
`liquidity`, `trades`.

## 7. Исследуем instruments

```sql
SELECT *
FROM instruments;
```

затем:

```sql
SELECT
    instrument_id,
    ticker,
    name
FROM instruments;
```

`SELECT *` выводит все колонки таблицы как есть. Второй вариант выводит только перечисленные
колонки, причём **в том порядке, в котором вы их перечислили** в запросе — это порядок
результата, а не порядок хранения данных в таблице.

Важно: сама таблица `instruments` при этом не меняется. `SELECT` — это чтение. Query Results —
временный результат именно этого чтения, а не новая сохранённая таблица.

Небольшая техническая деталь на будущее: SQLTools по умолчанию показывает в Query Results не
больше 50 строк за раз (настройка `sqltools.results.limit` в этом проекте не менялась, так что
действует значение по умолчанию). Для `instruments` это не имеет значения — там всего 12
строк, — но пригодится в следующем разделе.

## 8. Исследуем схему через PRAGMA

```sql
PRAGMA table_info('instruments');
```

Это тоже SQL — точнее, специальная команда SQLite (`PRAGMA`), которая тоже выполняется как
обычный запрос через SQLTools. Результат — по одной строке на каждую колонку таблицы
`instruments`, с полями:

- `name` — имя колонки;
- `type` — объявленный тип (`INTEGER`, `TEXT`, `REAL`, ...);
- `notnull` — `1`, если колонка обязательна (`NOT NULL`), `0` — если нет;
- `dflt_value` — значение по умолчанию, если оно задано, иначе пусто;
- `pk` — `0`, если колонка не входит в первичный ключ; любое число больше нуля означает, что
  колонка — часть `PRIMARY KEY` (а само число — её позиция в этом ключе).

Повторите то же самое для:

```sql
PRAGMA table_info('accounts');
```

и:

```sql
PRAGMA table_info('daily_prices');
```

Для `daily_prices` присмотритесь внимательно к колонке `pk` в результате: определите
самостоятельно, простой первичный ключ у этой таблицы или составной. Ответ и объяснение — в
`lessons/answers/01_answers.md`, но сначала попробуйте сами.

## 9. Исследуем внешние ключи

```sql
PRAGMA foreign_key_list('trades');
```

Вы увидите две строки — обе связи `trades` с другими таблицами: с `accounts` и с
`instruments`. Обратите внимание: порядок строк в результате не обязан совпадать с порядком, в
котором `FOREIGN KEY` были написаны в `CREATE TABLE`, — SQLite показывает их в своём
внутреннем порядке. Ориентируйтесь на колонки `table` (на какую таблицу ссылка), `from`
(колонка в `trades`) и `to` (колонка в таблице, на которую ссылаемся), а не на порядок строк.

Схематично обе связи выглядят так:

```text
accounts.account_id
        ↑
trades.account_id
```

```text
instruments.instrument_id
          ↑
trades.instrument_id
```

## 10. FOREIGN KEY всё ещё не JOIN

Это важно повторить именно сейчас, но уже на реальной базе, а не на маленьком примере из
урока 0.

```sql
SELECT
    trade_id,
    account_id,
    instrument_id,
    side
FROM trades;
```

(В этой таблице 230 строк, а Query Results по умолчанию показывает первые 50 — это ограничение
инструмента SQLTools, а не данных: все 230 строк реально есть в таблице.)

Посмотрите на результат: вы видите `account_id` и `instrument_id` — просто числа. Тикер
инструмента (`ticker`) и название счёта (`account_name`) **не появились** в результате сами по
себе, хотя `FOREIGN KEY` на обе эти таблицы в схеме объявлен.

Зафиксируем это явно: **наличие внешнего ключа не заставляет `SELECT` автоматически добавлять
данные родительской таблицы.** `FOREIGN KEY` контролирует, какие значения `account_id` и
`instrument_id` вообще допустимы при записи — это правило целостности, а не инструмент
получения данных. Получать данные из связанной таблицы автоматически будет `JOIN` — вы дойдёте
до него в уроке 4. Сейчас — на шаг раньше.

## 11. Ручное сопоставление без JOIN

Раз `JOIN` пока не используем, сопоставим данные сами, глазами — как в уроке 0, только на
настоящих торговых данных.

1. Получите список сделок:

   ```sql
   SELECT
       trade_id,
       account_id,
       instrument_id,
       side
   FROM trades;
   ```

2. Выберите взглядом одну конкретную строку — запомните её `trade_id`, `account_id` и
   `instrument_id`.

3. Отдельным запросом найдите инструмент по `instrument_id`:

   ```sql
   SELECT
       instrument_id,
       ticker,
       name
   FROM instruments;
   ```

4. Отдельным запросом найдите счёт по `account_id`:

   ```sql
   SELECT
       account_id,
       account_name,
       strategy
   FROM accounts;
   ```

Цель — почувствовать саму цепочку, которую позже за вас будет проходить `JOIN`:

```text
trade
 ↓
instrument_id
 ↓
instruments
 ↓
ticker
```

```text
trade
 ↓
account_id
 ↓
accounts
 ↓
account_name
```

`JOIN` пока не используем нигде в этом уроке — только три отдельных `SELECT` и сопоставление
результатов вручную.

## 12. Схема и данные — коротко закрепим разницу

```sql
SELECT *
FROM instruments;
```

— это **данные**: конкретные строки вроде `SBER`, `GAZP`, конкретных сделок и цен.

```sql
PRAGMA table_info('instruments');
```

— это **схема**: описание того, как эти данные организованы — какие есть колонки, какого они
типа, что обязательно, а что нет.

Схема отвечает на вопрос «как устроено», данные — на вопрос «что конкретно там лежит». Это два
разных вида информации об одной и той же таблице, и разные запросы возвращают то одно, то
другое.

## 13. Как подходить к незнакомой SQLite-базе

Это одна из главных практических идей урока: у вас теперь есть повторяемый алгоритм для
знакомства с **любой** новой SQLite-базой, не только с `trading_training.db`.

```text
Какие таблицы существуют?
        ↓
Какие у них колонки?
        ↓
Какие данные лежат внутри?
        ↓
Какие есть связи?
```

Соответствующий инструмент для каждого шага:

```sql
SELECT name, type
FROM sqlite_schema
WHERE type = 'table';
```

```sql
PRAGMA table_info('table_name');
```

```sql
SELECT *
FROM table_name;
```

```sql
PRAGMA foreign_key_list('table_name');
```

Именно эту последовательность вы только что прошли на `trading_training.db` — от списка
таблиц до внешних ключей `trades`. В следующий раз, когда вам дадут доступ к чужой базе (в
этом курсе или уже в реальной работе), начните с этих же четырёх шагов.
