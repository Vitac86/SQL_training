## 2. SELECT, DISTINCT, AS

Базовый `SELECT` с выбором колонок вы уже писали в уроке 1:

```sql
SELECT ticker, name, asset_class FROM instruments;
```

`DISTINCT` убирает повторяющиеся строки в результате:

```sql
SELECT DISTINCT asset_class FROM instruments;
```

Это покажет уникальный список классов активов (`equity`, `fx`, `bond`, `money_market`) — без
повторов, даже если в таблице несколько инструментов одного класса.

`AS` даёт колонке (или вычисляемому значению) другое имя в результате — это называется
"псевдоним" (alias):

```sql
SELECT ticker AS symbol, name AS instrument_name FROM instruments;
```

## 3. Вычисляемые колонки: quantity * price и ROUND

`SELECT` не обязан выводить только "сырые" колонки — можно сразу вычислять новые значения:

```sql
SELECT
    trade_id,
    quantity,
    price,
    quantity * price AS turnover
FROM trades
LIMIT 10;
```

`turnover` (оборот) — классический пример вычисляемой колонки в торговых данных: количество
бумаг, умноженное на цену сделки. Обратите внимание: `LIMIT 10` здесь используется просто как
знакомый вам с урока 1 способ не листать все 230 сделок — подробно `LIMIT` разберём чуть ниже
в этом же уроке.

### Зачем нужен ROUND

Посмотрите на одну конкретную сделку:

```sql
SELECT
    trade_id,
    quantity,
    price,
    quantity * price AS turnover
FROM trades
WHERE trade_id = 4;
```

(`WHERE` мы пока не проходили официально — разберём его в следующем разделе; здесь он просто
указывает на одну конкретную строку.) Результат: `quantity = 50`, `price = 72.04`, а
`turnover` окажется чем-то вроде `3602.0000000000005` — с "хвостом" из лишних цифр, хотя
`50 * 72.04` на бумаге равно ровно `3602`. Это не ошибка SQLite и не ошибка в данных: `price`
хранится как `REAL` (число с плавающей точкой), а такие числа физически не могут абсолютно
точно представить некоторые дробные значения в двоичной форме — это общая особенность чисел с
плавающей точкой в любом языке программирования, не только в SQL.

`ROUND` решает именно эту практическую проблему — округляет до нужного числа знаков после
запятой:

```sql
SELECT
    trade_id,
    quantity,
    price,
    ROUND(quantity * price, 2) AS turnover
FROM trades
WHERE trade_id = 4;
```

Теперь `turnover` — аккуратные `3602.0`. Второй аргумент `ROUND(..., 2)` — сколько знаков
после запятой оставить; для рублёвых сумм обычно достаточно двух.

## 4. WHERE и операторы сравнения

```sql
SELECT * FROM trades WHERE side = 'BUY';
SELECT * FROM trades WHERE quantity <> 100;
SELECT * FROM trades WHERE price > 1000;
SELECT * FROM trades WHERE price < 200;
SELECT * FROM trades WHERE quantity >= 500;
SELECT * FROM trades WHERE quantity <= 10;
```

`=` — равно, `<>` — не равно (в SQLite также работает `!=`), `>`, `<`, `>=`, `<=` — как в
математике.

### Эксперимент: меняем условие

Прежде чем выполнять следующий запрос, **сначала предположите**: сколько сделок, по-вашему,
будет с `side = 'BUY'` — примерно половина от 230, больше половины, меньше?

```sql
SELECT COUNT(*) FROM trades WHERE side = 'BUY';
```

Выполните, посмотрите на реальное число в Query Results. Теперь измените одно условие:

```sql
SELECT COUNT(*) FROM trades WHERE side = 'SELL';
```

Сравните два результата. Это тот же самый навык, который вы будете использовать постоянно:
поменять одно слово в уже написанном запросе и тут же увидеть, как изменился результат — не
обязательно перечитывать документацию, чтобы понять, что делает `side = 'SELL'`, если вы
только что видели, что делает `side = 'BUY'`.

## 5. AND, OR, NOT

```sql
SELECT * FROM trades WHERE side = 'BUY' AND quantity > 100;

SELECT * FROM trades WHERE side = 'BUY' OR side = 'SELL';

SELECT * FROM trades WHERE NOT side = 'BUY';
```

`AND` требует выполнения **обоих** условий одновременно, `OR` — хотя бы одного, `NOT`
инвертирует условие.

---

## 6. IN и BETWEEN

```sql
SELECT * FROM instruments WHERE asset_class IN ('fx', 'bond');

SELECT * FROM trades WHERE price BETWEEN 100 AND 300;
```

`IN` — короткая запись для "равно одному из перечисленных значений" (заменяет длинную цепочку
`OR`). `BETWEEN a AND b` включает обе границы (`a` и `b` тоже подходят).

---

## 7. LIKE

```sql
SELECT * FROM instruments WHERE ticker LIKE 'S%';
```

`%` — любое количество любых символов (в том числе ноль). `LIKE 'S%'` находит тикеры,
начинающиеся на `S` — в наших данных это `SBER` и `SU26238`.

```sql
SELECT * FROM instruments WHERE name LIKE '%банк%';
```

Это найдёт `'Сбербанк, ПАО, ао'` — `LIKE` ищет подстроку `'банк'` где угодно внутри строки.

### Важный нюанс: LIKE и кириллица

Попробуйте тот же запрос, но с заглавной буквы:

```sql
SELECT * FROM instruments WHERE name LIKE '%Банк%';
```

Результат — **пустой**, хотя `'Сбербанк'` явно есть в базе! Причина: по умолчанию SQLite
считает буквы регистронезависимыми в `LIKE` (то есть не различает `S` и `s`) только для
латинских ASCII-букв. Для кириллицы такого автоматического приведения регистра нет — `'Б'` и
`'б'` для `LIKE` в SQLite по умолчанию являются **разными** символами. Практический вывод для
работы с русским текстом: если `LIKE` неожиданно не находит то, что явно есть в таблице,
первым делом проверьте регистр букв, особенно для кириллицы.

## 8. IS NULL и IS NOT NULL

В наших учебных таблицах специально нет "пустых" (`NULL`) значений в ключевых полях —
благодаря `NOT NULL` из урока 0. Но важно знать: `NULL` нельзя сравнивать через `= NULL` —
это никогда не сработает, даже для по-настоящему пустых значений. Правильный синтаксис:

```sql
SELECT * FROM trades WHERE commission IS NOT NULL;

SELECT * FROM trades WHERE commission IS NULL;
```

Второй запрос вернёт пустой результат — в `trades.commission` нет `NULL`-значений, потому
что колонка объявлена как `NOT NULL`. Это ожидаемо и является хорошей проверкой того, что вы
верно понимаете разницу между `= NULL` (никогда не работает) и `IS NULL` (правильный способ).

## 9. ORDER BY, ASC, DESC

```sql
SELECT * FROM trades ORDER BY price;

SELECT * FROM trades ORDER BY price DESC;

SELECT * FROM trades ORDER BY trade_date ASC, price DESC;
```

По умолчанию `ORDER BY` сортирует по возрастанию (`ASC` можно не писать явно). `DESC` — по
убыванию. Можно сортировать по нескольким колонкам сразу: сначала по первой, а при совпадении
значений — по второй.

### Эксперимент: меняем направление сортировки

```sql
SELECT trade_id, trade_date
FROM trades
ORDER BY trade_date ASC
LIMIT 5;
```

Предположите, какие даты вы увидите, прежде чем выполнять запрос: самые ранние или самые
поздние сделки? Выполните и проверьте себя. Теперь измените одно слово:

```sql
SELECT trade_id, trade_date
FROM trades
ORDER BY trade_date DESC
LIMIT 5;
```

Сравните два результата в Query Results. `trade_id` в них, скорее всего, совсем разные — это
наглядно показывает, что `ORDER BY` меняет **порядок**, в котором строки покидают запрос, а не
то, какие строки в принципе туда попадают.

## 10. LIMIT

```sql
SELECT * FROM trades ORDER BY price DESC LIMIT 5;
```

Это классический паттерн "top N" — здесь: 5 самых дорогих по цене сделок.

## 11. Как читать порядок смысла в запросе

Когда в одном запросе одновременно есть `WHERE`, `ORDER BY` и `LIMIT`, полезно представлять
себе, в каком **логическом** порядке SQL как бы обрабатывает данные:

```text
FROM
 ↓
WHERE
 ↓
SELECT
 ↓
ORDER BY
 ↓
LIMIT
```

Важная оговорка: это **упрощённая модель для понимания смысла запроса**, а не описание того,
как SQLite на самом деле физически исполняет запрос внутри себя (там всё сложнее и завязано на
так называемый query planner — это отдельная большая тема на будущее, сейчас в неё не
углубляемся). Но как способ читать и понимать уже написанный запрос эта модель работает
надёжно.

Разберём по этой модели запрос:

```sql
SELECT
    trade_id,
    quantity * price AS turnover
FROM trades
WHERE side = 'BUY'
ORDER BY turnover DESC
LIMIT 5;
```

1. **`FROM trades`** — берём таблицу `trades` целиком (230 строк) как источник.
2. **`WHERE side = 'BUY'`** — оставляем только строки с покупками (110 из 230).
3. **`SELECT trade_id, quantity * price AS turnover`** — для оставшихся строк строим нужные
   колонки, в том числе вычисляемую `turnover`.
4. **`ORDER BY turnover DESC`** — сортируем результат по убыванию оборота.
5. **`LIMIT 5`** — берём только первые пять строк уже отсортированного результата.

Реальный результат в Query Results — пять самых крупных по обороту BUY-сделок (значения
округлены до целых для читаемости таблицы; в самом запросе `ROUND` намеренно не используется
— и строка `167` в Query Results честно покажет `3302000.0000000005`, тот же эффект
плавающей точки, что вы видели в разделе про `ROUND` выше):

| trade_id | turnover |
|---|---|
| 164 | 8 285 000 |
| 167 | 3 302 000 |
| 104 | 3 282 000 |
| 163 | 3 282 000 |
| 108 | 3 272 000 |

Обратите внимание на порядок в самом тексте запроса: `WHERE` в SQL пишется **до** `SELECT` по
синтаксису, но по смыслу (шаг 2 выше) выполняется раньше, чем шаг 3 — то есть раньше, чем
формируются итоговые колонки. Это нормально: порядок написания ключевых слов в SQL и порядок
их смыслового выполнения — разные вещи, и умение мысленно их разделять — важный навык для
чтения чужих запросов.
