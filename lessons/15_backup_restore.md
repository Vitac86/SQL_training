# Урок 15. Резервное копирование и восстановление

**Цель:** понимать, чем BACKUP отличается от экспорта CSV и почему без проверки восстановления копия недостаточна.

## Что защищаем

БД хранит таблицы, индексы и другие объекты, а также журнал транзакций. **Полная резервная копия** (`FULL BACKUP`) даёт согласованную базовую точку восстановления. **Дифференциальная** — изменения после последней полной копии. Резервные копии **журнала транзакций** применяются при соответствующей модели восстановления (FULL/BULK_LOGGED) и корректно организованной цепочке бэкапов. Не путай полную копию с recovery model FULL.

- **RPO** — допустимая потеря данных во времени.
- **RTO** — допустимое время восстановления.
- Резервная копия, которую никогда не проверяли через восстановление, — **неподтверждённая защита**.

SQL Server Express поддерживает BACKUP/RESTORE; **SQL Server Agent** для автоматического расписания в Express не доступен, поэтому планировщик/автоматизация потребует другого механизма.

## Выбрать место для файлов

```sql
SELECT CAST(SERVERPROPERTY('InstanceDefaultBackupPath') AS NVARCHAR(4000))
       AS default_backup_folder;
```

**Важное различие:** файл бэкапа создаёт **служба SQL Server**, а не SSMS. Поэтому папка должна существовать **на машине сервера**, а служебная учётная запись SQL Server должна иметь право записи. Путь `C:\\SQL` на твоём компьютере может быть недоступен серверу или не иметь нужных прав. На локальном экземпляре удобнее использовать штатную папку Backup, подсказанную сервером.

## Создать резервную копию через SSMS

В Object Explorer: `Databases → TradingTraining → Tasks → Back Up...`; тип **Full**, выбрать доступный путь, выполнить. Сохрани полученный полный путь.

Альтернатива — T-SQL (сначала **замени путь** на доступный сервису SQL Server):

```sql
-- Пример; НЕ запускать, пока путь не проверен:
-- BACKUP DATABASE TradingTraining
-- TO DISK = N'C:\\<папка SQL Server Backup>\\TradingTraining_full.bak'
-- WITH INIT, CHECKSUM, STATS = 10;
```

## Проверка и тестовое восстановление

`RESTORE VERIFYONLY FROM DISK = N'...';` проверяет читаемость и структуру резервной копии, **но не заменяет полноценное тестовое восстановление**. Для тренировки восстанавливай в **другую базу** (например, `TradingTraining_RestoreTest`), а не поверх рабочей. Перед RESTORE изучи логические имена файлов через `RESTORE FILELISTONLY`, используй `WITH MOVE` и существующие пути к файлам.
