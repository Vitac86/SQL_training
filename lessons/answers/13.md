# Ответы к уроку 13 — транзакции и ошибки

[Вернуться к уроку](../13_транзакции_и_ошибки.md)

## 1. Атомарность на примере перевода

Операция состоит из двух шагов: списать 100 со счёта A и зачислить 100 на счёт B. Если один шаг провалится, **нужно отменить оба**, иначе средства будут потеряны или созданы «из воздуха». Это и означает атомарность.

## 2. Увеличить лимит и откатить

```sql
USE TradingTraining;
BEGIN TRANSACTION;
UPDATE dbo.accounts
SET risk_limit_rub = risk_limit_rub + 1000
WHERE account_id = 6;

SELECT risk_limit_rub FROM dbo.accounts WHERE account_id = 6;
ROLLBACK TRANSACTION;
SELECT risk_limit_rub FROM dbo.accounts WHERE account_id = 6;
```

Ожидается **501000.00**, затем **500000.00**. Выполни блок целиком; не оставляй транзакцию открытой.

## 3. Попытка вставить отрицательное quantity, обработать ошибку

```sql
BEGIN TRY
    BEGIN TRANSACTION;

    INSERT INTO dbo.trades
        (trade_id, trade_date, account_id, instrument_id,
         side, quantity, price, commission)
    VALUES (900013, '20240109', 1, 1, 'BUY', -10, 100, 0);

    ROLLBACK TRANSACTION;
END TRY
BEGIN CATCH
    SELECT ERROR_NUMBER() AS error_no,
           ERROR_MESSAGE() AS error_message;
    IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;
END CATCH;
```

В сообщении ожидается имя **CK_trades_quantity** (формулировка и код ошибки зависят от ситуации/версии). В `dbo.trades` не появится запись `900013`. `CHECK(quantity > 0)` задано в `database/01_schema.sql`.

## 4. CHECK против TRY/CATCH

**CHECK** — постоянное правило *допустимости данных*, связанное с таблицей. **TRY/CATCH** — способ обработать *ошибку выполнения*, например вывести сообщение и откатить транзакцию. Второе не создаёт и не заменяет первое.

## 5. Можно ли отменить COMMIT через ROLLBACK

Нет. `ROLLBACK` отменяет **ещё не зафиксированную** работу текущей транзакции. После COMMIT предыдущие значения могут потребовать резервной копии, истории изменений или новой корректирующей операции. Учебные UPDATE не фиксируй COMMIT.
