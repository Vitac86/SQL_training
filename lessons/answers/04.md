# Ответы к уроку 04 — ключи и связи

[Вернуться к уроку](../04_ключи_и_связи.md)

## 1. Первичные ключи

- `dbo.accounts`: `account_id`.
- `dbo.instruments`: `instrument_id`.
- `dbo.trades`: `trade_id`.

**PK** — уникальный и обязательный идентификатор строки внутри соответствующей таблицы.

## 2. Почему instrument_id=3 — не «третья сделка»

`instrument_id` — номер записи **в справочнике инструментов**. Номер самой сделки — `trade_id`. У множества разных сделок может быть одинаковый `instrument_id=3`, то есть все эти сделки относятся к LKOH.

```sql
USE TradingTraining;
SELECT TOP (5) trade_id, instrument_id
FROM dbo.trades WHERE instrument_id = 3
ORDER BY trade_id;
```

## 3. Составной ключ дневных цен

Одна дата содержит цены **многих инструментов**: `price_date` повторяется. Один инструмент имеет цены **за многие даты**: `instrument_id` повторяется. Уникальна **пара** `(price_date, instrument_id)`. Поэтому PK составной.

## 4. Где увидеть ключи в SSMS

Разверни **TradingTraining → Tables → dbo.trades → Keys**. Там ты увидишь первичный ключ `PK_trades` и внешние ключи `FK_trades_account`, `FK_trades_instrument` (в зависимости от версии SSMS отображение может отличаться).

Если хочешь увидеть сам SQL, нажми правой кнопкой на `dbo.trades` → **Script Table as → CREATE To → New Query Editor Window**. Полученный скрипт **не запускай**, он нужен для просмотра.

## 5. Зачем FK, если есть JOIN

`FOREIGN KEY` работает как **правило записи**: «не разрешай `instrument_id`, которого нет в instruments». `JOIN` — команда **чтения**: «возьми сделку и найди для неё название инструмента». FK сам по себе не добавляет тикер в результат SELECT.
