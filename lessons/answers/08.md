# Ответы к уроку 08 — INSERT, UPDATE, DELETE и откат

[Вернуться к уроку](../08_изменение_данных.md)

**Безопасность:** каждый изменяющий пример ниже выполняй **целиком** в одном окне SSMS, включая `ROLLBACK`. Если прервёшь исполнение после `BEGIN TRANSACTION`, завершай незакрытую транзакцию **в том же соединении**. Эти упражнения рассчитаны только на `TradingTraining`.

## 1. Увеличить лимит на 5% и откатить

```sql
USE TradingTraining;
BEGIN TRANSACTION;

UPDATE dbo.accounts
SET risk_limit_rub = risk_limit_rub * 1.05
WHERE account_id = 6;

SELECT account_id, risk_limit_rub
FROM dbo.accounts
WHERE account_id = 6;

ROLLBACK TRANSACTION;

SELECT account_id, risk_limit_rub
FROM dbo.accounts
WHERE account_id = 6;
```

Во время транзакции — **525000.00**, после ROLLBACK — **500000.00**.

## 2. Временно изменить strategy

```sql
BEGIN TRANSACTION;

UPDATE dbo.accounts
SET strategy = 'training'
WHERE account_id = 6;

SELECT account_name, strategy FROM dbo.accounts WHERE account_id = 6;

ROLLBACK TRANSACTION;

SELECT account_name, strategy FROM dbo.accounts WHERE account_id = 6;
```

Перед откатом `strategy='training'`, после — `'none'`.

## 3. Временно удалить пустой счёт

```sql
BEGIN TRANSACTION;

DELETE FROM dbo.accounts WHERE account_id = 6;
SELECT COUNT(*) AS during_delete FROM dbo.accounts WHERE account_id = 6;

ROLLBACK TRANSACTION;

SELECT COUNT(*) AS after_rollback FROM dbo.accounts WHERE account_id = 6;
```

Сначала результат счётчика **0**, после ROLLBACK — **1**. Это возможно, потому что у счёта 6 нет дочерних сделок, а транзакция ещё не зафиксирована.

## 4. Зачем SELECT перед UPDATE

Сначала:

```sql
SELECT * FROM dbo.accounts WHERE account_id = 6;
```

Убедись, что WHERE выбирает **именно одну нужную строку**. Если забыть `WHERE` в UPDATE, сервер изменит все строки таблицы. Проверочный SELECT снижает риск ошибиться с условием.

## 5. COMMIT и ROLLBACK

`COMMIT` фиксирует выполненные изменения; `ROLLBACK` отменяет ещё **не зафиксированные** изменения текущей транзакции. После COMMIT обычным ROLLBACK уже не вернуть предыдущие значения. В этих примерах **не используй COMMIT**.
