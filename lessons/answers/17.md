# Ответы к уроку 17 — права и безопасность

[Вернуться к уроку](../17_права_и_безопасность.md)

## 1. Узнать login и user

```sql
USE TradingTraining;
SELECT ORIGINAL_LOGIN() AS login_name,
       USER_NAME() AS database_user;
```

**Значения зависят от твоего подключения**, поэтому готовую конкретную строку заранее указать нельзя. `ORIGINAL_LOGIN()` показывает имя входа при открытии сеанса; `USER_NAME()` — текущего пользователя базы.

## 2. Где Logins и Users

В **Object Explorer → [сервер] → Security → Logins** — имена входа на сервер. В **Databases → TradingTraining → Security → Users** — пользователи **этой конкретной базы**. Сервер может содержать много БД с разными правами.

## 3. Минимальные права по ролям

Пример корректного распределения:

- **Аналитик** — `SELECT` только разрешённых отчётных таблиц/VIEW, без права `UPDATE`/ `DELETE`.
- **Оператор** — право выполнять нужную процедуру приёма поручения (`EXECUTE`), не обязательно прямой INSERT в любую таблицу.
- **Администратор** — права настройки и обслуживания в рамках обязанностей; полный `sysadmin` не должен выдаваться всем.

**Единственного набора ролей не существует:** реальные разрешения определяет модель доступа и требования безопасности.

## 4. SELECT против UPDATE

`GRANT SELECT` разрешает **читать** данные. `GRANT UPDATE` разрешает **менять существующие** записи (в пределах области разрешения). Право UPDATE само по себе не означает право DELETE или неограниченный доступ ко всей базе.

В учебной базе пока **не меняй права**: достаточно правильно объяснить разницу.
