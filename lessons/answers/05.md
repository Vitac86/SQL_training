# Ответы к уроку 05 — CREATE TABLE и ограничения

[Вернуться к уроку](../05_создание_таблицы_и_check.md)

**Условие:** таблица `dbo.lesson05_orders` создана, как указано в уроке. Если ты уже удалил её через `DROP TABLE`, сначала заново пройди шаг создания в уроке. Не запускай INSERT дважды с одинаковым `order_id`.

## 1. Добавить корректную запись

```sql
USE TradingTraining;
INSERT INTO dbo.lesson05_orders (order_id, ticker, quantity)
VALUES (4, 'MOEX', 15);

SELECT * FROM dbo.lesson05_orders
WHERE order_id = 4;
```

Ожидается одна строка: `4 | MOEX | 15`. Это допустимые значения.

## 2. quantity=0

```sql
INSERT INTO dbo.lesson05_orders (order_id, ticker, quantity)
VALUES (5, 'SBER', 0);
```

**Ожидается ошибка** проверки `CK_lesson05_quantity`, потому что `CHECK (quantity > 0)` не допускает ни отрицательные числа, ни **0**. В таблице не появится `order_id=5`.

## 3. order_id=NULL

```sql
INSERT INTO dbo.lesson05_orders (order_id, ticker, quantity)
VALUES (NULL, 'GAZP', 10);
```

**Ожидается ошибка**, потому что первичный ключ (`PRIMARY KEY`) не может быть NULL. В нашем определении столбец также отмечен `NOT NULL`.

## 4. Где посмотреть CHECK

1. В файле `database/01_schema.sql` или в коде `CREATE TABLE dbo.lesson05_orders`.
2. В **Object Explorer → dbo.lesson05_orders → Constraints** (если папка отображается в твоей версии SSMS).
3. Запросом:

```sql
SELECT name, definition
FROM sys.check_constraints
WHERE parent_object_id = OBJECT_ID('dbo.lesson05_orders');
```

Ожидается `CK_lesson05_quantity` с условием `quantity > 0`.

## 5. CHECK и WHERE — разные задачи

**WHERE** выбирает строки при **чтении**. Например, `SELECT ... WHERE quantity > 0` лишь показывает подходящие записи. **CHECK** — постоянное правило таблицы: сервер **отклоняет INSERT или UPDATE**, если записываемое значение нарушает правило.

Важно: не называй CHECK «частью INSERT»: оно записано в схеме таблицы и действует для всех программ, пишущих в неё.
