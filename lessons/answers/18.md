# Ответы к уроку 18 — резервное копирование

[Вернуться к уроку](../18_резервное_копирование.md)

## 1. Полный backup в SSMS

Путь интерфейса: **Object Explorer → Databases → TradingTraining → Tasks → Back Up...**. В диалоге выбери тип **Full**, проверь место назначения, запусти операцию. Признак успешного выполнения — сообщение SSMS об успешном завершении и появление файла `.bak` по указанному серверному пути.

**Не выполняй Restore поверх TradingTraining** ради проверки задания.

## 2. Путь и права

```sql
SELECT CAST(SERVERPROPERTY('InstanceDefaultBackupPath') AS NVARCHAR(4000))
    AS backup_folder;
```

Конкретный путь зависит от установки SQL Server. Бэкап создаёт **служба SQL Server**, значит права записи в этот каталог нужны её **служебной учётной записи**. Путь на компьютере пользователя не обязательно существует на машине SQL Server.

## 3. Зачем тестовое восстановление

Создание файла `.bak` ещё не доказывает, что систему удастся быстро вернуть к работе. Для надёжной проверки восстанавливают в **отдельную тестовую БД** и проверяют целостность, таблицы и доступность. `RESTORE VERIFYONLY` полезен, но не заменяет полноценное тестовое восстановление.

## 4. RPO и RTO

**RPO** — максимально допустимая потеря данных во времени, например 5 минут. **RTO** — максимально допустимое время восстановления работоспособности, например 30 минут. Это разные требования: даже частый backup не гарантирует быстрое восстановление.

## 5. Почему CSV не заменяет backup

CSV-файл `trades` обычно содержит лишь **значения строк одной таблицы**. Полный backup SQL Server сохраняет сведения и данные, необходимые для восстановления базы, включая её объекты и структуру; отдельный CSV не содержит правила CHECK/FK, индексы, процедуры и другие объекты.
