# Ответы к уроку 19 — качество данных

[Вернуться к уроку](../19_качество_данных.md)

## 1. Контроль пяти количеств

```sql
USE TradingTraining;
SELECT N'instruments' AS table_name, COUNT(*) AS actual FROM dbo.instruments
UNION ALL SELECT N'accounts', COUNT(*) FROM dbo.accounts
UNION ALL SELECT N'trades', COUNT(*) FROM dbo.trades
UNION ALL SELECT N'daily_prices', COUNT(*) FROM dbo.daily_prices
UNION ALL SELECT N'liquidity', COUNT(*) FROM dbo.liquidity;
```

Ожидается **12, 6, 230, 429, 429** соответственно, если учебная база не менялась.

## 2. Дубли по ticker

```sql
SELECT ticker, COUNT(*) AS cnt
FROM dbo.instruments
GROUP BY ticker
HAVING COUNT(*) > 1;
```

Ожидается **0 строк**: уникальность тикера защищена ограничением `UQ_instruments_ticker`.

## 3. Недопустимые quantity/price

```sql
SELECT trade_id, quantity, price
FROM dbo.trades
WHERE quantity <= 0 OR price <= 0;
```

Ожидается **0 строк**, потому что в схеме заданы `CK_trades_quantity` и `CK_trades_price`. Если ограничения кто-то отключил/обошёл при импорте, проверка может выявить проблемы.

## 4. До JOIN и после JOIN

```sql
SELECT COUNT(*) AS base_trades FROM dbo.trades;

SELECT COUNT(*) AS joined_trades
FROM dbo.trades AS t
JOIN dbo.instruments AS i ON i.instrument_id = t.instrument_id
JOIN dbo.accounts AS a ON a.account_id = t.account_id;
```

Ожидается **230 и 230**. У каждой сделки есть **один действующий** счёт и один инструмент. Если вместо соединения по ключам добавить таблицу с многими подходящими строками, количество может увеличиться — это риск ошибочного отчёта.

## 5. Почему сумма может быть экономически бессмысленной

У разных инструментов цена и количество имеют **разные единицы измерения**, множители, валюты и правила котирования. Арифметическая сумма `quantity*price` может быть вычислена SQL верно, но не представлять «общий рублёвый оборот». Для экономически корректного расчёта нужны спецификация инструментов и правила конвертации.
