# Ответы к уроку 16 — представления, процедуры, временные таблицы

[Вернуться к уроку](../16_views_процедуры_временные_таблицы.md)

## 1. VIEW с четырьмя полями

Выполни целиком в SSMS:

```sql
USE TradingTraining;
GO
CREATE OR ALTER VIEW dbo.v_lesson16_trades
AS
SELECT t.trade_id, i.ticker, a.account_name, t.commission
FROM dbo.trades AS t
JOIN dbo.instruments AS i ON i.instrument_id = t.instrument_id
JOIN dbo.accounts AS a ON a.account_id = t.account_id;
GO

SELECT TOP (5) *
FROM dbo.v_lesson16_trades
ORDER BY trade_id;
```

Ожидается **5 строк**, четыре столбца. `GO` отделяет пакет создания VIEW; обычный VIEW хранит определение запроса, а не всю копию данных.

## 2. PROCEDURE для счёта 6

После создания процедуры **из урока 16**:

```sql
EXEC dbo.usp_TradesByAccount @AccountId = 6;
```

Ожидается **0 строк**, так как `ACC-DORMANT` не имеет сделок. Если процедура не найдена, сначала выполни `CREATE OR ALTER PROCEDURE` из урока — сама по себе она не появляется.

## 3. Временная таблица с комиссиями по счетам

```sql
DROP TABLE IF EXISTS #fees_by_account;

SELECT account_id, SUM(commission) AS total_fee
INTO #fees_by_account
FROM dbo.trades
GROUP BY account_id;

SELECT * FROM #fees_by_account ORDER BY account_id;

DROP TABLE #fees_by_account;
```

`SELECT ... INTO #...` **создаёт** временную таблицу и вставляет результат. В ней только счета со сделками, потому что исходная группировка идёт по `trades`.

## 4. CTE против #temp

CTE — именованное выражение **одного следующего запроса**; не является постоянной сохранённой таблицей. `#temp` создаётся физически в `tempdb` и может использоваться в нескольких командах одного подключения, пока существует.

## 5. Почему нужен ORDER BY в SELECT к VIEW

SQL-результат не имеет гарантированного порядка без **внешнего `ORDER BY`**. Даже если внутренняя реализация VIEW когда-то возвращала строки одинаково, полагаться на это нельзя: план выполнения может меняться.
