## 1. Сделки за январь 2024

```sql
USE TradingTraining;
SELECT trade_id, trade_date, price
FROM dbo.trades
WHERE trade_date >= '20240101'
  AND trade_date < '20240201'
ORDER BY trade_date, trade_id;
```

Границы: **1 января включительно**, **1 февраля не включительно**. Такой способ удобен и для `DATETIME2`, где внутри дня есть часы, минуты и секунды.

## 2. Простая и средневзвешенная цена SBER

```sql
SELECT AVG(price) AS simple_average_price,
       SUM(CAST(quantity AS DECIMAL(19,4)) * price)
          / NULLIF(SUM(CAST(quantity AS DECIMAL(19,4))), 0)
          AS weighted_average_price
FROM dbo.trades
WHERE instrument_id = 1;
```

`AVG(price)` придаёт каждой сделке одинаковый вес; второй показатель учитывает **количество бумаг** в каждой сделке. `NULLIF(...,0)` предотвращает деление на ноль. Это упрощённый расчёт по всем сторонам BUY/SELL; для реального торгового VWAP необходимо отдельно определить стороны, период и единицы измерения.

## 3. Комиссия по месяцам

```sql
SELECT YEAR(trade_date) AS trade_year,
       MONTH(trade_date) AS trade_month,
       SUM(commission) AS commission_total
FROM dbo.trades
GROUP BY YEAR(trade_date), MONTH(trade_date)
ORDER BY trade_year, trade_month;
```

Одна строка результата — **один календарный месяц определённого года**. Не группируй только по номеру месяца, иначе январь разных лет соединится в одну группу.

## 4. Почему это не обязательно рублёвый оборот

`quantity * price` имеет смысл только после определения **единицы количества и цены**: у акции и облигации могут быть разные котировочные правила, у валютного инструмента — другая валюта расчёта, у дериватива — множитель контракта. Складывать значения без нормализации валют/единиц некорректно.
