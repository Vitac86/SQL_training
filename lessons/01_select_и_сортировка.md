# Урок 01. SELECT: как управлять результатом запроса

**Знакомо из урока 00:** таблицы, строки и столбцы, `SELECT`, `FROM`, `TOP`, `ORDER BY`. **Новое:** понятный порядок написания, `AS`, `DISTINCT`, сортировка по нескольким полям, выражения в SELECT.

## 1. Один запрос — один конкретный вопрос

В реальной работе запрос начинается не со слова SELECT, а с вопроса: «Какие столбцы нужны? Из какой таблицы? В каком порядке?»

Например: «Покажи номера, даты и цены пяти первых по номеру сделок».

```sql
USE TradingTraining;

SELECT TOP (5)
       trade_id,
       trade_date,
       price
FROM dbo.trades
ORDER BY trade_id;
```

Подумай: если вместо `price` поставить `quantity`, изменится ли **число строк**? Нет: изменится только набор столбцов.

## 2. SELECT * или перечислить поля?

```sql
SELECT *
FROM dbo.accounts;
```

`*` значит «все столбцы». Для знакомства с таблицей удобно, но в регулярном отчёте лучше указать конкретные поля:

```sql
SELECT account_id, account_name, strategy
FROM dbo.accounts;
```

Почему? Читатель сразу понимает, что входит в отчёт. Если структура таблицы изменится, запрос с явным списком столбцов обычно предсказуемее.

## 3. Переименуем столбцы результата

```sql
SELECT
    ticker AS symbol,
    [name] AS instrument_name
FROM dbo.instruments;
```

`AS symbol` означает «в результате назови столбец symbol». **Имя столбца в самой базе не изменится**. Это как временная подпись для отчёта.

Проверка: вернись в Обозреватель объектов → `dbo.instruments` → **Столбцы / Columns**. Там по-прежнему `ticker`, а не `symbol`.

## 4. Сортировка: ORDER BY

```sql
SELECT trade_id, quantity, price
FROM dbo.trades
ORDER BY price DESC;
```

`DESC` — от большего к меньшему. `ASC` — от меньшего к большему; это направление по умолчанию.

Теперь сравни:

```sql
SELECT TOP (5) trade_id, quantity, price
FROM dbo.trades
ORDER BY price DESC, trade_id ASC;
```

Первый сортируемый столбец — цена. Если цены одинаковые, внутри равной цены решает номер сделки. Это называется **сортировкой по нескольким полям**.

Без `ORDER BY` SQL Server не обещает порядок строк, даже если на экране они выглядят отсортированными.

## 5. DISTINCT: оставить только разные значения

```sql
SELECT strategy FROM dbo.accounts;
```

Здесь шесть строк (по одной на счёт). В другом наборе стратегии могли бы повторяться. Чтобы оставить только **разные значения**, пишут:

```sql
SELECT DISTINCT strategy
FROM dbo.accounts
ORDER BY strategy;
```

`DISTINCT` смотрит на **всю выбранную комбинацию столбцов**, а не на один «особый» столбец. Так, `DISTINCT account_id, strategy` может дать все шесть строк: account_id у каждой строки разный.

## 6. Можно вычислять новые столбцы

Предположим, ты хочешь увидеть цену, количество и простое произведение «количество × цена»:

```sql
SELECT TOP (5)
       trade_id,
       quantity,
       price,
       quantity * price AS amount_example
FROM dbo.trades
ORDER BY trade_id;
```

`amount_example` **не хранится** отдельным столбцом в `trades`: SQL Server вычислил число для выдачи. Этот пример — арифметическая иллюстрация, не универсальный расчёт рублёвого оборота (у разных финансовых инструментов бывают разные множители и единицы измерения).

## 7. Полезный приём в SSMS

В редакторе можно держать несколько запросов подряд, разделяя их точкой с запятой. Выдели **только один запрос** и нажми F5. Так не нужно открывать новое окно для каждого упражнения.

`GO`, которое видно в стартовых скриптах, — отдельная команда среды SSMS для границы пакетов. Пока самостоятельно использовать её не нужно.
