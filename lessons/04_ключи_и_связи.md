# Урок 04. Зачем нужны ключи и как таблицы связаны между собой

**Знакомо:** таблица, столбец, тип, WHERE. **Новое:** идентификатор, первичный ключ (PK), внешний ключ (FK), связь «один ко многим». Пока только исследуем готовую базу.

## 1. Зачем инструменту отдельный номер

Посмотри:

```sql
USE TradingTraining;

SELECT TOP (5) instrument_id, ticker, [name]
FROM dbo.instruments
ORDER BY instrument_id;
```

Результат начинается так:

```text
instrument_id | ticker | name
1             | SBER   | Сбербанк, ПАО, ао
2             | GAZP   | Газпром, ПАО, ао
3             | LKOH   | Лукойл, ПАО, ао
```

Человеку удобен тикер, компьютеру — стабильный **идентификатор**. `instrument_id = 3` означает конкретную запись об LKOH.

**Первичный ключ** (`PRIMARY KEY`, или **PK**) — столбец или набор столбцов, который однозначно определяет строку. Он не может быть NULL, и две строки не могут иметь одинаковый ключ. В `dbo.instruments` это `instrument_id`. А в `dbo.trades` — `trade_id`.

## 2. Сделка знает номер инструмента

```sql
SELECT trade_id, instrument_id, account_id, side, quantity
FROM dbo.trades
WHERE trade_id = 1;
```

Первая сделка содержит `instrument_id = 3` и `account_id = 5`. Найдём их описания самостоятельно двумя запросами:

```sql
SELECT instrument_id, ticker
FROM dbo.instruments
WHERE instrument_id = 3;

SELECT account_id, account_name
FROM dbo.accounts
WHERE account_id = 5;
```

Получишь `LKOH` и `ACC-FIXEDINCOME`.

Зачем не копировать название прямо в каждую сделку? Если переименовать инструмент, придётся исправлять его название во множестве сделок. А при отдельной таблице достаточно исправить **одну строку справочника**.

## 3. Внешний ключ — правило, которое связывает таблицы

`trades.instrument_id` содержит номера из `instruments.instrument_id`. Такая ссылка называется **внешним ключом** (`FOREIGN KEY`, или **FK**).

Простыми словами: «если записываешь сделку с instrument_id = 3, инструмент с номером 3 **должен существовать**».

То же для `account_id`. В одну сторону: у каждой сделки один счёт. В другую: один счёт может иметь много сделок. Это называют **связью один-ко-многим**.

```text
instruments: instrument_id=3 (LKOH)
             │
             ├── trades.trade_id=1, instrument_id=3
             ├── trades.trade_id=... , instrument_id=3
             └── trades.trade_id=... , instrument_id=3
```

Здесь мы пока мысленно сопоставляем две таблицы **по номерам**. В уроке 07 вместо трёх отдельных SELECT научимся делать это одним запросом с JOIN.

## 4. Где ключи видны в SSMS

В Object Explorer раскрой `dbo.trades`:

- **Columns / Столбцы** — сами поля.
- **Keys / Ключи** — некоторые ограничения ключей, включая PK и связи FK.
- **Constraints / Ограничения** — другие проверочные правила, если они созданы.

Вид представления может отличаться между версиями SSMS. Альтернативный способ увидеть определения: правой кнопкой по `dbo.trades` → **Script Table as → CREATE To → New Query Editor Window**. **Не запускай** этот скрипт — таблица уже существует; просто почитай. В следующем уроке разберём подобный код на маленькой таблице, которую создадим сами.

## 5. Ещё одна разновидность ключа: составной

У `daily_prices` есть столбцы `price_date`, `instrument_id`, `close_price`. Для одной даты существует **много инструментов**. Для одного инструмента — **много дат**. Поэтому уникальна пара:

```text
(price_date, instrument_id)
```

Такой первичный ключ из нескольких столбцов называется **составным**.

**Самопроверка:** PK: `account_id`, `instrument_id`, `trade_id`. Внешний ключ указывает на **другую таблицу**, а не на позицию строки в списке.
