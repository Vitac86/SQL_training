# Урок 00. Что такое база данных и как увидеть её в SSMS

**Уровень:** первый урок. **Цель:** не заучить определения, а увидеть, где хранятся данные и как задавать простые вопросы. На занятие достаточно 30–45 минут.

**Ты уже подготовил:** локальный SQL Server, программу SSMS и базу `TradingTraining` через четыре файла из `database/`. Если нет — начни с [инструкции](../SETUP_WINDOWS.md).

## 1. От знакомого к новому: представь Excel

Есть небольшой журнал сделок:

```text
Номер | Дата       | Тикер | Операция | Количество | Цена
1     | 09.01.2024 | LKOH  | SELL     | 10         | 7099.03
2     | 09.01.2024 | GMKN  | SELL     | 500        | 142.92
```

**Строка** — одна сделка. **Столбец** — свойство сделки, например цена. **Таблица** — набор строк с одинаковыми столбцами. Похоже на лист Excel.

Когда таких записей много и к ним одновременно обращаются разные программы, нужен механизм надёжного хранения, поиска и изменения. Организованное хранилище называют **базой данных (БД)**. Программа, которая управляет им, — **системой управления базами данных (СУБД)**.

В нашем случае:

- **SQL Server** — СУБД: хранит таблицы и выполняет команды.
- **SSMS** — программа, в которой ты пишешь команды и смотришь ответ. Она **не хранит базу вместо SQL Server**.
- **SQL** — язык команд: например, «покажи все инструменты».

```text
Ты → вводишь SQL в SSMS → SSMS отправляет запрос → SQL Server
Ты ← видишь таблицу результатов ← SQL Server возвращает ответ
```

## 2. Исследуем SSMS по ходу работы

Слева находится **Обозреватель объектов / Object Explorer**. Он похож на Проводник Windows: раскрываешь папки и видишь содержимое. Найди:

```text
Имя твоего сервера
└─ Базы данных / Databases
   └─ TradingTraining
      └─ Таблицы / Tables
         ├─ dbo.accounts
         ├─ dbo.instruments
         ├─ dbo.trades
         ├─ dbo.daily_prices
         └─ dbo.liquidity
```

Не все объекты могут быть в видимой части дерева; разверни папки. Если недавно создал базу, но её нет в списке: правой кнопкой на **Базы данных** → **Обновить / Refresh**.

`TradingTraining` — название всей нашей БД. `dbo.trades` — таблица сделок. Начало `dbo.` пока воспринимай как часть полного названия: что оно означает, разберём позже.

**Попробуй без SQL:** правой кнопкой на `dbo.instruments` → **Выбрать первые 1000 строк / Select Top 1000 Rows**. В нижней части появятся данные, а сверху — SQL, который SSMS написала за тебя. Ты только что выполнил свой первый запрос через интерфейс.

## 3. Первый запрос вручную

Нажми сверху **Создать запрос / New Query**. Это просто текстовое окно для SQL. Вставь:

```sql
SELECT 1 AS answer;
```

Нажми **F5** (кнопка «Выполнить» делает то же самое). Ниже увидишь вкладку **Результаты / Results** с числом `1`. Команда `SELECT` означает «покажи». `AS answer` — «назови столбец answer».

Во вкладке **Сообщения / Messages** SQL Server показывает сообщения о выполнении или ошибки. Если что-то не получилось, смотри туда: это одно из главных мест в SSMS.

Когда в редакторе несколько запросов, **выделяй** нужный текст перед F5: иначе SSMS попытается выполнить весь текст окна.

## 4. Выбираем нужную БД

На одном сервере может быть несколько баз. Напиши:

```sql
USE TradingTraining;
SELECT DB_NAME() AS selected_database;
```

Результат — `TradingTraining`.

- `USE TradingTraining` — «следующие команды выполняй в этой базе».
- `DB_NAME()` — готовая команда-функция, возвращающая выбранное имя. Устройство функций изучим позднее.

Также вверху редактора есть **выпадающий список баз данных**. Он позволяет выбрать ту же БД мышкой.

## 5. Читаем таблицу

```sql
SELECT *
FROM dbo.instruments;
```

Перевод на русский: «покажи **все столбцы** (`*`) **из** (`FROM`) таблицы `dbo.instruments`». Результат: **12 инструментов**, среди них `SBER`, `GAZP`, `LKOH`.

А теперь только тикеры:

```sql
SELECT ticker
FROM dbo.instruments;
```

Результат: всё ещё 12 строк, но **один столбец**. Мы не удалили другие столбцы — просто попросили сервер их не показывать.

Ещё один пример:

```sql
SELECT instrument_id, ticker
FROM dbo.instruments;
```

Теперь два столбца. Сравни с предыдущим результатом.

## 6. Покажем несколько записей, а не весь журнал

```sql
SELECT TOP (5) trade_id, trade_date, quantity, price
FROM dbo.trades
ORDER BY trade_id;
```

- `TOP (5)` — показать не более пяти строк.
- `ORDER BY trade_id` — отсортировать по номеру сделки, от меньшего к большему.
- Остальное уже знакомо: выбираем столбцы из таблицы.

Ожидаемые номера сделок: **1, 2, 3, 4, 5**. Замени `TOP (5)` на `TOP (3)`: должны остаться сделки 1–3. Если убрать `ORDER BY`, нельзя гарантировать, **какие именно** три строки придут первыми.

## 7. Попросим SQL Server посчитать строки

```sql
SELECT COUNT(*) AS trades_count
FROM dbo.trades;
```

Ответ: **230**. `COUNT(*)` означает «посчитай строки». Подробно будем изучать подсчёты в уроке 06; пока это просто полезная готовая команда.

```sql
SELECT COUNT(*) AS accounts_count
FROM dbo.accounts;
```

Ответ: **6**. Видишь, мы задаём один и тот же вопрос двум разным таблицам и получаем разные ответы.

## 8. Что ты сейчас знаешь

БД хранит таблицы. SQL Server обслуживает БД, SSMS помогает с ним общаться. `SELECT` читает данные, `FROM` указывает таблицу, `TOP` ограничивает число строк, `ORDER BY` задаёт порядок вывода. Никакой запрос в этом уроке **не меняет данные**.

**Проверь себя без подсказки:**

1. Выведи все строки и столбцы `dbo.accounts`. Сколько счетов?
2. Выведи из `dbo.instruments` только `ticker` и `[name]`.
3. Покажи первые три сделки по возрастанию `trade_id`.
4. Объясни своими словами, чем SSMS отличается от SQL Server.

**Ответы для самопроверки:** 6 счетов; 12 строк с тикером и названием; первые trade_id — 1, 2, 3. В вопросе 4 важна мысль: SSMS — интерфейс, SQL Server — движок, который хранит и обрабатывает данные.
