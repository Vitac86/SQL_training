# Урок 02. WHERE: выбираем нужные строки

**Знакомо:** SELECT отвечает, *что показать*; FROM — *из какой таблицы*; ORDER BY — *в каком порядке*. **Новое:** WHERE, сравнения, несколько условий, IN, BETWEEN, LIKE, NULL.

## 1. Как Excel-фильтр, но в SQL

В Excel можно отфильтровать строки со значением BUY. В SQL эту задачу выполняет `WHERE`.

```sql
USE TradingTraining;

SELECT TOP (10) trade_id, side, quantity, price
FROM dbo.trades
WHERE side = 'BUY'
ORDER BY trade_id;
```

Читается так: «Возьми сделки, **оставь только** те, где `side` равно BUY, покажи четыре столбца, отсортируй по номеру и оставь десять первых».

Строка `'BUY'` взята в одинарные кавычки, потому что это **текст**. Число `100` не нужно оборачивать в кавычки.

## 2. Сравнения

```sql
SELECT trade_id, price
FROM dbo.trades
WHERE price > 5000
ORDER BY price DESC, trade_id;
```

Другие операции: `=` равно, `<>` не равно, `>` больше, `<` меньше, `>=` больше или равно, `<=` меньше или равно.

Микроэксперимент: замени `>` на `>=`; объясни, какие строки **теоретически** могли добавиться.

## 3. Два условия: AND, OR и скобки

```sql
SELECT trade_id, side, quantity
FROM dbo.trades
WHERE side = 'SELL' AND quantity >= 200
ORDER BY trade_id;
```

`AND` — **оба** условия должны выполняться. `OR` — **хотя бы одно**.

```sql
SELECT ticker, asset_class
FROM dbo.instruments
WHERE asset_class = 'fx' OR asset_class = 'bond'
ORDER BY ticker;
```

Если пишешь одновременно AND и OR, **используй скобки**:

```sql
SELECT trade_id, side, quantity
FROM dbo.trades
WHERE (side = 'BUY' OR side = 'SELL')
  AND quantity > 1000;
```

Мы явно показываем, какие условия считаются вместе.

## 4. IN, BETWEEN, LIKE

```sql
-- Один из перечисленных вариантов:
SELECT ticker FROM dbo.instruments
WHERE asset_class IN ('equity', 'fx');

-- В пределах включительно 100 ... 200:
SELECT trade_id, price FROM dbo.trades
WHERE price BETWEEN 100 AND 200;

-- Начинается на букву S:
SELECT ticker FROM dbo.instruments
WHERE ticker LIKE 'S%';
```

В `LIKE 'S%'` знак `%` означает «после S могут идти любые символы». Поведение поиска по регистру зависит от настроек сравнения строк (позже объясним, что такое **collation**).

## 5. Отсутствующее значение: NULL

Пока представь новый столбец «комментарий к сделке»: не у каждой сделки будет комментарий. SQL использует специальное значение **NULL**: «значение отсутствует или неизвестно».

Не путай:
- `0` — число ноль;
- `''` — пустой текст;
- `NULL` — значение не указано.

Для NULL нельзя писать `= NULL` или `<> NULL`. Нужно `IS NULL` или `IS NOT NULL`.

```sql
SELECT trade_id, price
FROM dbo.trades
WHERE price IS NULL;
```

Результат: **0 строк**, потому что в нашей таблице цена обязательна (это правило задано при подготовке базы; самостоятельно создавать правила научимся в уроке 05). Однако сам оператор `IS NULL` нужен, когда в некоторых таблицах значение действительно может отсутствовать.

**Почему не `= NULL`?** Если значение неизвестно, вопрос «оно равно чему-то?» тоже не имеет известного ответа. SQL использует в таких условиях третий возможный результат — **UNKNOWN**, помимо TRUE и FALSE. WHERE оставляет только строки с TRUE. Подробности нужны позднее; пока запомни правило `IS NULL`.

## 6. Проверяем понимание

Запусти три запроса и сравни:

```sql
SELECT COUNT(*) AS all_trades FROM dbo.trades;
SELECT COUNT(*) AS buys FROM dbo.trades WHERE side = 'BUY';
SELECT COUNT(*) AS sells FROM dbo.trades WHERE side = 'SELL';
```

Сравни: сумма BUY + SELL должна равняться **230**, потому что все сделки нашего набора имеют одно из двух значений. `COUNT(*)` пока используем как счётчик; подробно он будет в уроке 06.
