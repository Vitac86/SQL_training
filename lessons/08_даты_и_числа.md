# Урок 08. Даты, денежная арифметика и пропущенные значения

**Цель:** не терять точность в финансовой аналитике.

## Типы данных и точность

Для денежных цен и комиссий используй `DECIMAL(p, s)`: \(p\) — общее число значащих десятичных цифр, \(s\) — число цифр после запятой. `FLOAT` хранит приблизительные двоичные значения; `ROUND` меняет представление результата, **не исправляя** ошибочный исходный тип и не определяя правила финансового округления. В нашей базе цены `DECIMAL(19,4)`, количества `BIGINT`. При умножении проверяй потенциальное переполнение и результативный scale; для денежных вычислений нужна согласованная политика точности.

**Цена и объём одного инструмента** могут иметь особую единицу измерения (лот, номинал, котировка в процентах, валютная пара). Поэтому `quantity * price` в учебном наборе — условный notional, **не гарантированно рублёвый оборот**.

```sql
USE TradingTraining;
SELECT TOP (10) trade_id, quantity, price,
       CAST(quantity AS DECIMAL(19,4)) * price AS raw_notional,
       ROUND(CAST(quantity AS DECIMAL(19,4)) * price, 2) AS rounded_notional
FROM dbo.trades ORDER BY trade_id;
```

## DATE, DATETIME2, интервалы

`DATE` хранит календарную дату, `DATETIME2` — момент с точностью до долей секунды (без тайм-зоны), `DATETIMEOFFSET` — значение со смещением. Не называй столбец типа `TIMESTAMP` «временем»: в SQL Server это устаревший синоним `ROWVERSION`.

```sql
SELECT trade_id, trade_date
FROM dbo.trades
WHERE trade_date >= CONVERT(date, '20240201', 112)
  AND trade_date <  CONVERT(date, '20240301', 112)
ORDER BY trade_date, trade_id;
```

Полуоткрытый диапазон `>= start AND < next` удобен и для `DATETIME2`: не требует угадывать последнюю долю секунды месяца. `DATEDIFF(day, start, end)` считает **пересечённые границы дат**, а не обязательно точное число 24-часовых интервалов.

```sql
SELECT TRY_CONVERT(date, N'31.12.2024', 104) AS parsed_date,
       DATEADD(day, 7, CONVERT(date, '20240109', 112)) AS plus_week,
       EOMONTH(CONVERT(date, '20240209', 112)) AS month_end;
```

`TRY_CONVERT` при плохом формате даёт NULL; всегда проверяй такие строки, а не молча отбрасывай.

## Денежные расчёты и отсутствие данных

```sql
SELECT i.ticker, COUNT(t.trade_id) AS trades_count,
       COALESCE(SUM(t.commission), 0) AS total_commission
FROM dbo.instruments AS i
LEFT JOIN dbo.trades AS t ON t.instrument_id = i.instrument_id
GROUP BY i.ticker;
```

`COALESCE` приемлем для **суммы комиссии** при отсутствии сделок (0); но нулевая **цена** вместо неизвестной обычно будет ошибкой. `NULLIF(denominator, 0)` защитит от деления на ноль, вернув NULL вместо аварийного результата.
