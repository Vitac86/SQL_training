# Урок 16. Контроль качества данных и системная диагностика

**Цель:** формировать контрольные SQL-проверки и замечать ошибки раньше, чем они попадут в отчёты.

## Контроли качества по слоям

1. **Структурный:** типы, NOT NULL, PK, FK, CHECK.
2. **Бизнес-логический:** цена > 0, сторона из списка, допустимость дат, отсутствие дублей внешних IDs.
3. **Межтабличный:** сделки ссылаются на действующие счета и инструменты; цены совпадают по дате и инструменту; нет неожиданных размножений JOIN.
4. **Временной:** данные не пропали за нужную дату, не пришли с задержкой, измерения корректно историзируются.
5. **Сверочный:** количество, сумма, расхождения с источником/учётной системой, контроль идемпотентности загрузки.

## Практические проверки

```sql
USE TradingTraining;
-- Дубли сделок по ID невозможны благодаря PK.
SELECT trade_id, COUNT(*) AS duplicates
FROM dbo.trades
GROUP BY trade_id
HAVING COUNT(*) > 1;

-- Ссылки на несущестующие инструменты: обычно пусто из-за FK.
SELECT t.trade_id
FROM dbo.trades AS t
LEFT JOIN dbo.instruments AS i ON i.instrument_id = t.instrument_id
WHERE i.instrument_id IS NULL;

-- Есть ли пропущенная цена закрытия в дату исполнения?
SELECT COUNT(*) AS trades_without_daily_price
FROM dbo.trades AS t
LEFT JOIN dbo.daily_prices AS p
  ON p.instrument_id = t.instrument_id AND p.price_date = t.trade_date
WHERE p.instrument_id IS NULL;
```

Результат последней проверки **не следует заранее считать нулём**: наличие котировки на дату сделки зависит от набора данных и логики источника. Пустая связь — не обязательно ошибка рынка, но сигнал проверить.

## Мониторинг собственных запросов

```sql
SELECT DB_NAME() AS db_name,
       COUNT(*) AS business_table_count
FROM sys.tables
WHERE name IN ('accounts','instruments','trades','daily_prices','liquidity');

SELECT name, recovery_model_desc, state_desc
FROM sys.databases WHERE name = 'TradingTraining';

SELECT OBJECT_NAME(object_id) AS table_name, name AS index_name, type_desc
FROM sys.indexes
WHERE object_id = OBJECT_ID(N'dbo.trades');
```

Системные представления `sys.*` описывают метаданные; DMV `sys.dm_*` показывают состояние/статистику, но часто требуют расширенных прав. План выполнения доступен в SSMS. `SET STATISTICS IO, TIME ON` — стандартная первая проверка дорогого запроса.

## Диагностика результата до оптимизации

Правильный запрос начинается с вопроса **«верное ли количество строк и зерно данных?»**. Если к одной сделке присоединить все дневные цены инструмента без даты, получишь ошибочную кратность; никакой индекс не исправит неверный `ON`.
