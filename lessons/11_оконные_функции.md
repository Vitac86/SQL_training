# Урок 11. Оконные функции: показываем и строку, и показатель рядом

**Знакомо:** GROUP BY превращает 230 сделок в несколько строк итогов. **Новое:** `OVER`, `ROW_NUMBER`, `LAG`, накопительная сумма и скользящая средняя.

## 1. Почему GROUP BY иногда неудобен

Представь отчёт «каждая сделка SBER и её порядковый номер по дате». Если использовать GROUP BY, строки склеятся в группы — мы потеряем детализацию каждой сделки. Нужно что-то, что считает **рядом с отдельной строкой**, но её не удаляет.

Это и делает **оконная функция**: смотрит на набор соседних или связанных строк и вычисляет значение для каждой исходной строки.

## 2. Нумеруем сделки внутри инструмента

```sql
USE TradingTraining;

SELECT
    trade_id, instrument_id, trade_date,
    ROW_NUMBER() OVER (
        PARTITION BY instrument_id
        ORDER BY trade_date, trade_id
    ) AS sequence_no
FROM dbo.trades
ORDER BY instrument_id, sequence_no;
```

Разберём в знакомых словах:

- `ROW_NUMBER()` — порядковый номер: 1, 2, 3...
- `PARTITION BY instrument_id` — для **каждого инструмента** начинай нумерацию заново.
- `ORDER BY trade_date, trade_id` **внутри OVER** — в каком порядке присваивать номера.
- Последний `ORDER BY` **снаружи** — в каком порядке **показать** строки пользователю.

Мы не сгруппировали сделки в одну строку: каждой сделке дали её номер.

## 3. Последняя сделка по каждому инструменту

```sql
WITH numbered AS (
    SELECT trade_id, instrument_id, trade_date, price,
           ROW_NUMBER() OVER (
               PARTITION BY instrument_id
               ORDER BY trade_date DESC, trade_id DESC
           ) AS rn
    FROM dbo.trades
)
SELECT trade_id, instrument_id, trade_date, price
FROM numbered
WHERE rn = 1
ORDER BY instrument_id;
```

Сначала CTE (урок 09) нумерует сделки, начиная с самой новой для инструмента. Потом внешний SELECT оставляет только `rn=1`. Почему нельзя фильтровать `ROW_NUMBER()` напрямую через WHERE на том же уровне? Потому что **WHERE отбирает исходные строки раньше, чем вычисляется оконный столбец**.

## 4. LAG: получить предыдущее значение

Дневные цены SBER:

```sql
SELECT price_date, close_price,
       LAG(close_price) OVER (ORDER BY price_date) AS prev_close
FROM dbo.daily_prices
WHERE instrument_id = 1
ORDER BY price_date;
```

`LAG(close_price)` — значение `close_price` у предыдущей строки **по указанному порядку**. Для первого дня предыдущего значения нет, поэтому `prev_close = NULL`.

Усложним на один шаг и посчитаем **изменение**:

```sql
WITH x AS (
    SELECT price_date, close_price,
           LAG(close_price) OVER (ORDER BY price_date) AS prev_close
    FROM dbo.daily_prices
    WHERE instrument_id = 1
)
SELECT price_date, close_price, prev_close,
       close_price - prev_close AS price_change
FROM x
ORDER BY price_date;
```

Для первой даты разница будет NULL — это правильно, потому что сравнивать не с чем.

## 5. Накопительный итог

```sql
SELECT trade_id, account_id, commission,
       SUM(commission) OVER (
           PARTITION BY account_id
           ORDER BY trade_date, trade_id
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_fee
FROM dbo.trades
WHERE account_id = 1
ORDER BY trade_date, trade_id;
```

Перевод `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`: «от самой первой строки этой группы до текущей». Для каждой следующей сделки общая комиссия увеличивается.

Здесь появились **рамки окна** — правило, какие строки участвуют в расчёте конкретной записи. Без явной рамки при `ORDER BY` возможны неожиданные эффекты для равных значений.

## 6. Скользящее среднее за пять наблюдений

```sql
SELECT price_date, close_price,
       AVG(close_price) OVER (
           ORDER BY price_date
           ROWS BETWEEN 4 PRECEDING AND CURRENT ROW
       ) AS avg_last_5
FROM dbo.daily_prices
WHERE instrument_id = 1
ORDER BY price_date;
```

Смысл: для каждой даты средняя цена **текущего и четырёх предыдущих наблюдений**. Первые дни будут рассчитаны по меньшему количеству наблюдений, потому что более ранних нет. **Пять наблюдений ≠ пять календарных дней** (выходные и праздники).

## 7. Когда GROUP BY, а когда OVER

- «Сколько сделок по каждому счёту?» → GROUP BY.
- «Покажи каждую сделку и её порядковый номер в рамках счёта» → ROW_NUMBER/OVER.
- «Как цена изменилась относительно предыдущего дня?» → LAG.
- «Как менялся накопленный итог комиссии после каждой сделки?» → SUM/OVER с рамкой.
