# Урок 06. COUNT, SUM, AVG и GROUP BY: превращаем сделки в показатели

**Знакомо:** читаем сделки через SELECT, фильтруем через WHERE, сортируем. **Новое:** агрегатная функция (сворачивает много строк в одно значение), GROUP BY и HAVING.

## 1. Начнём с одного понятного вопроса

«Сколько сделок в таблице?»

```sql
USE TradingTraining;

SELECT COUNT(*) AS trades_count
FROM dbo.trades;
```

Ответ — **230**. Мы уже делали это в уроке 00. Теперь поймём механизм: `COUNT(*)` получает **множество строк** и считает, сколько их.

## 2. Другие полезные агрегаты

```sql
SELECT
    COUNT(*) AS trade_count,
    SUM(commission) AS total_commission,
    AVG(commission) AS avg_commission,
    MIN(commission) AS min_commission,
    MAX(commission) AS max_commission
FROM dbo.trades;
```

`SUM` — сумма; `AVG` — среднее арифметическое; `MIN` и `MAX` — минимум и максимум.

Заметь: исходно 230 строк, а результат — **одна строка со сводными показателями**. Это важно: агрегаты отвечают не на вопрос «какая комиссия у сделки 1?», а «какие комиссии у всех сделок вместе?».

## 3. Группировка: один показатель для каждого счёта

«Сколько сделок приходится **на каждый счёт**?»

```sql
SELECT account_id, COUNT(*) AS trade_count
FROM dbo.trades
GROUP BY account_id
ORDER BY account_id;
```

`GROUP BY account_id` мысленно раскладывает сделки в отдельные стопки по номеру счёта, после чего `COUNT(*)` работает с каждой стопкой. Ты получишь несколько строк, по одной на счёт **с сделками**.

Аналогично для BUY/SELL:

```sql
SELECT side, COUNT(*) AS trade_count
FROM dbo.trades
GROUP BY side
ORDER BY side;
```

Ожидается **две строки** — BUY и SELL. Их количества вместе равны 230.

## 4. WHERE до подсчёта, HAVING после

Если вопрос «сколько **BUY** по каждому счёту?» — сначала оставляем BUY, потом группируем:

```sql
SELECT account_id, COUNT(*) AS buys
FROM dbo.trades
WHERE side = 'BUY'
GROUP BY account_id
ORDER BY account_id;
```

Но если вопрос «покажи **только счета, у которых больше 40 сделок**», то нужно отфильтровать уже **готовые группы**:

```sql
SELECT account_id, COUNT(*) AS trade_count
FROM dbo.trades
GROUP BY account_id
HAVING COUNT(*) > 40
ORDER BY trade_count DESC;
```

**Ключевое различие:**
- `WHERE` — отбор отдельных **исходных строк**.
- `HAVING` — отбор **групп после подсчёта**.

Не стоит писать `WHERE COUNT(*) > 40`: это не работает, потому что подсчёт ещё не сделан на этапе WHERE.

## 5. Показатели по дням

```sql
SELECT trade_date,
       COUNT(*) AS trade_count,
       SUM(commission) AS fees
FROM dbo.trades
GROUP BY trade_date
ORDER BY trade_date;
```

Одна строка теперь означает **одну дату**, а не одну сделку. Это называют «детализация отчёта» или **зерно данных**: нужно точно знать, что представляет одна строка результата.

## 6. Важный нюанс: сумма по финансовым инструментам

```sql
SELECT instrument_id,
       SUM(quantity * price) AS example_notional
FROM dbo.trades
GROUP BY instrument_id
ORDER BY instrument_id;
```

Числа вычисляются правильно математически. Но это **ещё не рублёвый оборот**: акции, облигации, валюта и ставки могут иметь разные единицы цены и размер контракта. Для настоящего отчёта нужен смысл каждого инструмента. Точность и денежные расчёты подробно разберём в уроке 10.

## 7. COUNT(*) и COUNT(column)

`COUNT(*)` считает строки, а `COUNT(column)` — строки, где **в выбранном столбце не NULL**. В наших `trades` PK обязателен, поэтому числа совпадают:

```sql
SELECT COUNT(*) AS all_rows, COUNT(trade_id) AS non_null_ids
FROM dbo.trades;
```

Но в сочетании с `LEFT JOIN` они могут различаться. Это увидим уже в следующем уроке.
