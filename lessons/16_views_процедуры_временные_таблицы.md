# Урок 16. VIEW, PROCEDURE и временные таблицы — разные способы переиспользовать SQL

**Знакомо:** запросы, CTE, CREATE TABLE, транзакции. **Новое:** представление (VIEW), процедура (PROCEDURE), временная таблица (#temp), параметры.

## 1. Представление VIEW: «запрос с именем»

Мы уже много раз писали JOIN сделок со счетами и инструментами. Представь, что похожий запрос нужен каждый день. Вместо копирования текста можно **сохранить определение запроса** в БД под именем.

```sql
USE TradingTraining;
GO
CREATE OR ALTER VIEW dbo.v_trades_with_names
AS
SELECT t.trade_id, t.trade_date, a.account_name, i.ticker,
       t.side, t.quantity, t.price, t.commission
FROM dbo.trades AS t
JOIN dbo.accounts AS a ON a.account_id = t.account_id
JOIN dbo.instruments AS i ON i.instrument_id = t.instrument_id;
GO
```

**Новое слово `GO`**: команда **SSMS**, отделяющая один пакет команд от другого. Она нужна здесь, потому что `CREATE VIEW` должен выполняться в отдельном пакете. Сам SQL Server не понимает GO как SQL-оператор.

Теперь читаем VIEW как таблицу:

```sql
SELECT TOP (10) *
FROM dbo.v_trades_with_names
ORDER BY trade_id;
```

Обычный VIEW обычно хранит **текст запроса, а не копию всех результатов**. Он удобен для отчётов и единой логики названий.

В SSMS VIEW появится в папке **Views / Представления**. При необходимости обнови список правой кнопкой по папке → Refresh.

## 2. Процедура: команда, которой можно передать параметр

А если нужно «покажи сделки **конкретного счёта**»? Можно один раз сохранить инструкцию с переменной `@AccountId`:

```sql
CREATE OR ALTER PROCEDURE dbo.usp_TradesByAccount
    @AccountId INT
AS
BEGIN
    SELECT trade_id, trade_date, instrument_id, quantity, price
    FROM dbo.trades
    WHERE account_id = @AccountId
    ORDER BY trade_date, trade_id;
END;
GO
```

`@AccountId INT` — **параметр**: значение, которое передадут при вызове. Запускаем:

```sql
EXEC dbo.usp_TradesByAccount @AccountId = 1;
```

Та же процедура работает и для 2, 3, 4... — без копирования и редактирования её текста.

**Разница:** VIEW представляет набор данных, к которому обращаются SELECT. PROCEDURE — готовая серверная команда, которая может принимать параметры, выполнять несколько действий и, если так запрограммировано, менять данные.

В SSMS процедуры находятся внутри базы в папке **Programmability → Stored Procedures / Программирование → Хранимые процедуры**.

## 3. Временная таблица: «черновик на время работы»

Ты уже знаешь **CTE**: именованный промежуточный результат одного запроса. Но что если промежуточные данные нужны **нескольким следующим запросам**? Можно создать временную таблицу:

```sql
SELECT account_id, COUNT(*) AS trade_count
INTO #account_counts
FROM dbo.trades
GROUP BY account_id;

SELECT * FROM #account_counts ORDER BY account_id;

DROP TABLE #account_counts;
```

`#account_counts` — **локальная временная таблица**. Она существует в пределах подключения и соответствующей области видимости, физически использует системную базу `tempdb`. `SELECT ... INTO` **создаёт** её и сразу записывает результат SELECT. `DROP TABLE` в конце очищает пример.

Если ты повторно запустишь фрагмент **до DROP**, имя может оказаться занято. Для повторного запуска в том же подключении можно сначала выполнить `DROP TABLE IF EXISTS #account_counts;`.

## 4. Когда что использовать

- Нужен удобный «слой» поверх JOIN для многих SELECT — **VIEW**.
- Нужна одна оформленная серверная операция с параметрами — **PROCEDURE**.
- Нужен промежуточный расчёт внутри **одного** сложного запроса — **CTE**.
- Нужно сохранить промежуточные строки между несколькими операторами — **#temp**.
