# Урок 08. INSERT, UPDATE, DELETE и как отменять пробные изменения

**Знакомо:** в уроке 05 мы добавляли строки через INSERT; в остальных уроках только читали. **Новое:** UPDATE, DELETE, простая транзакция как способ безопасного эксперимента.

## 1. Три вида изменения данных

- `INSERT` — добавить новую строку (уже видели).
- `UPDATE` — изменить существующую.
- `DELETE` — удалить существующую.

**Отличие от SELECT:** SELECT показывает, а эти команды меняют хранилище. Поэтому на боевой базе с ними особенно осторожны. Здесь — только наша `TradingTraining`.

## 2. Сначала посмотрим, что хотим менять

```sql
USE TradingTraining;

SELECT account_id, account_name, risk_limit_rub
FROM dbo.accounts
WHERE account_id = 6;
```

Ожидается `ACC-DORMANT` с лимитом **500000.00**. Допустим, мы хотим временно прибавить 1000 к лимиту и убедиться, что умеем это делать.

## 3. Новая идея: транзакция — «попробовать и отменить»

Вспомни черновик: можно вписать изменение, посмотреть результат и выбросить черновик. Транзакция позволяет выполнить серию действий **без окончательного сохранения**, пока ты не решишь их зафиксировать.

- `BEGIN TRANSACTION` — начать такую серию.
- `ROLLBACK TRANSACTION` — отменить изменения серии.
- `COMMIT TRANSACTION` — сохранить изменения окончательно.

Сейчас будем использовать **только ROLLBACK**, чтобы исходная база оставалась неизменной.

## 4. UPDATE: меняем значение и возвращаем обратно

**Выдели весь фрагмент от BEGIN до последнего SELECT и выполни целиком**:

```sql
BEGIN TRANSACTION;

UPDATE dbo.accounts
SET risk_limit_rub = risk_limit_rub + 1000
WHERE account_id = 6;

SELECT account_id, risk_limit_rub
FROM dbo.accounts WHERE account_id = 6;

ROLLBACK TRANSACTION;

SELECT account_id, risk_limit_rub
FROM dbo.accounts WHERE account_id = 6;
```

В первом результате после UPDATE — **501000.00**, во втором после ROLLBACK — снова **500000.00**.

Разбор: `SET` показывает новое значение, `WHERE` выбирает, какую строку менять. **Если забыть WHERE, UPDATE затронет все строки**. Поэтому перед UPDATE полезно выполнить SELECT с точно таким же WHERE.

> Если выполнить только BEGIN и UPDATE, а потом закрыть/забыть окно, можно оставить транзакцию открытой и блокировать работу. Всегда доводи учебный эксперимент до ROLLBACK.

## 5. DELETE: удаляем пробную строку и откатываем

`ACC-DORMANT` выбран специально: это счёт без сделок, поэтому его удаление не конфликтует со ссылками других таблиц.

```sql
BEGIN TRANSACTION;

DELETE FROM dbo.accounts
WHERE account_id = 6;

SELECT * FROM dbo.accounts WHERE account_id = 6;

ROLLBACK TRANSACTION;

SELECT * FROM dbo.accounts WHERE account_id = 6;
```

Сначала SELECT внутри транзакции покажет **0 строк**, затем после отмены счёт вернётся. **Не выполняй DELETE вне транзакции** во время этих упражнений.

## 6. Когда INSERT, UPDATE и DELETE не разрешают действие

В уроке 05 ты сам создал `CHECK`, `NOT NULL`, `PRIMARY KEY`. Правила работают при **любых изменениях**, не только INSERT. Например, попытка сделать `risk_limit_rub = -100` нарушает ограничение `CHECK (risk_limit_rub > 0)`, заданное в стартовой схеме.

Это помогает защищать данные даже тогда, когда ошибается пользователь или программа.

## 7. Связи тоже защищают данные

Если попытаться удалить справочник инструмента, на который ссылаются сделки, SQL Server может отклонить удаление из-за **FOREIGN KEY** (урок 04). Без такого правила мы могли бы оставить сделки с номером несуществующего инструмента.

## 8. Общее правило безопасности

Прежде чем запускать изменение, выясни:

1. **Какая таблица?**
2. **Какие строки затронет WHERE?**
3. **Можно ли отменить?** Для учебных изменений сначала BEGIN, в конце ROLLBACK.

Подробнее про атомарность, ошибки и ситуацию, когда два пользователя одновременно меняют данные, — в уроках 13–14. Сейчас этого достаточно.
