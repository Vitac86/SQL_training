# Урок 14. Безопасность SQL Server: login, user, role, GRANT

**Цель:** разделять аутентификацию, авторизацию и владение объектами.

## Понятия

**Login** — возможность аутентифицироваться на уровне экземпляра SQL Server. **Database user** — субъект внутри конкретной базы; обычно связан с login, но есть и другие модели. **Database role** — набор прав. **Schema** — пространство имён и объект управления владением. **GRANT** выдаёт разрешение, **DENY** явно запрещает (со своими правилами наследования/исключений), **REVOKE** отзывает явное предоставление/запрет.

Используй принцип **least privilege**: аналитике на чтение не нужны db_owner, sysadmin и права изменения таблиц. В production разделяют роли чтения, записи, исполнения процедур и администрирования. Не храни пароль в SQL-скриптах или в git.

## Посмотреть собственную сессию и полномочия

```sql
USE TradingTraining;
SELECT ORIGINAL_LOGIN() AS login_name,
       USER_NAME() AS database_user,
       SUSER_SNAME() AS effective_login;

SELECT name, type_desc
FROM sys.database_principals
WHERE type IN ('S', 'U', 'G', 'R')
ORDER BY name;
```

Информация системных каталогов может быть ограничена полномочиями текущего пользователя.

## Инъекции: почему параметры обязательны

Никогда не собирай SQL так: `'SELECT ... WHERE account_name = ''' + user_input + ''''`. Приложения должны передавать значения как параметры драйвера. В T-SQL для динамической команды — `sp_executesql @stmt, @params, @AccountName = ...`. Имена таблиц/колонок не параметризуются как значения; если динамика необходима, используй белый список имён и `QUOTENAME`.
