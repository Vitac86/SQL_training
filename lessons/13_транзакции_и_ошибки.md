# Урок 13. Транзакции: что происходит при ошибке посередине операции

**Знакомо:** в уроке 08 мы делали `BEGIN TRANSACTION → UPDATE → ROLLBACK`. **Новое:** фиксация, атомарность, обработка ошибок через TRY/CATCH, основы ACID.

## 1. Зачем нужны транзакции из нескольких шагов

Представь перевод денег между двумя счетами:

1. Уменьшить остаток на одном.
2. Увеличить остаток на другом.

Что если после первого шага программа упадёт? Деньги «исчезнут». Нужно требование: **либо сделаны оба шага, либо не сделан ни один**.

Транзакция объединяет изменения в **одну логическую операцию**. Это не особенность банков: точно так же можно согласованно записывать поручение и резервировать лимит.

## 2. Три команды из урока 08

```sql
USE TradingTraining;

BEGIN TRANSACTION;
UPDATE dbo.accounts
SET risk_limit_rub = risk_limit_rub + 1000
WHERE account_id = 6;

SELECT risk_limit_rub FROM dbo.accounts WHERE account_id = 6;

ROLLBACK TRANSACTION;
```

После ROLLBACK снова старое значение. Если бы вместо него выполнили COMMIT, изменение было бы зафиксировано. **На учебной базе пока оставляй ROLLBACK.**

## 3. Введём TRY/CATCH — только теперь

Когда ошибки ожидаемы, хочется не оставлять незаконченную транзакцию. Для этого в T-SQL есть конструкция:

```text
TRY   → попробовать выполнить действия
CATCH → если возникла перехватываемая ошибка, выполнить обработку
```

Пример: специально попытаемся нарушить знакомое правило CHECK и **выполним безопасный откат**:

```sql
BEGIN TRY
    BEGIN TRANSACTION;

    INSERT INTO dbo.trades
        (trade_id, trade_date, account_id, instrument_id,
         side, quantity, price, commission)
    VALUES (900013, '20240109', 1, 1,
            'BUY', -10, 100, 0);

    ROLLBACK TRANSACTION;
END TRY
BEGIN CATCH
    SELECT ERROR_NUMBER() AS error_number,
           ERROR_MESSAGE() AS error_message;

    IF @@TRANCOUNT > 0
        ROLLBACK TRANSACTION;
END CATCH;
```

**Построчно:**
- `BEGIN TRY` — начало блока, в котором может возникнуть ошибка.
- `INSERT` — пытаемся записать сделку с отрицательным количеством.
- SQL Server проверяет ограничение `CK_trades_quantity` (создано ещё в `database/01_schema.sql`).
- Проверка `quantity > 0` не проходит, INSERT отклоняется, управление переходит в CATCH.
- `ERROR_NUMBER()`, `ERROR_MESSAGE()` — показывают номер и текст ошибки.
- `@@TRANCOUNT` — есть ли у соединения открытая транзакция (число > 0).
- `ROLLBACK` отменяет всё, что ещё не было зафиксировано.

Обрати внимание: **TRY/CATCH не создаёт ограничение** и не решает, допустимо ли количество. Он только помогает **реагировать на ошибку**. Именно это в старой версии курса было показано слишком рано.

## 4. Четыре свойства ACID простыми словами

**A — Atomicity (атомарность).** Все изменения вместе или ни одного.

**C — Consistency (согласованность).** База соблюдает заданные правила: уникальность номеров, FK, CHECK. Сервер не угадывает бизнес-правила, которые мы забыли описать.

**I — Isolation (изоляция).** Когда два пользователя работают одновременно, их действия не должны произвольно ломать друг друга. Способы изоляции различаются — это тема следующего урока.

**D — Durability (долговечность).** После успешного COMMIT данные должны пережить сбой в пределах гарантий хранения и конфигурации SQL Server.

## 5. Почему одного TRY/CATCH недостаточно

`TRY/CATCH` перехватывает **не все** виды ошибок (например, часть ошибок компиляции на том же уровне). После некоторых ошибок транзакция становится **непригодной для COMMIT**, поэтому профессиональный код проверяет `XACT_STATE()`, а для многих сценариев использует `SET XACT_ABORT ON`.

Это не нужно запоминать с первого раза. Главное — понимать **какая часть отвечает за что**: CHECK проверяет данные, транзакция группирует изменения, TRY/CATCH помогает правильно завершить работу при ошибке.

## 6. Что делать, если что-то зависло после UPDATE

В SSMS один редактор обычно связан с отдельным подключением. Если ты оставил `BEGIN TRANSACTION` без COMMIT/ROLLBACK, могут продолжать удерживаться блокировки. Выполни в **том же окне** `ROLLBACK TRANSACTION;`, если транзакция действительно открыта. Не запускай произвольные ROLLBACK на других подключениях.
