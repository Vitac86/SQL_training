# Урок 10. Даты, точность чисел и финансовые расчёты

**Знакомо:** типы данных, WHERE, арифметика, GROUP BY. **Новое:** интервалы дат, работа с точностью DECIMAL, средневзвешенная цена, деление на ноль.

## 1. Почему в финансах важно договориться об единицах измерения

Сделка имеет `quantity` и `price`. На первый взгляд оборот равен `quantity * price`. Но у акции цена может означать рубли за штуку, у облигации — проценты от номинала, а у валютной пары — количество рублей за единицу другой валюты.

Поэтому в учебных примерах мы называем произведение **условной стоимостью**. Нельзя просто сложить полученные значения для разных инструментов и назвать итог рублёвым оборотом. Реальный отчёт требует **валюту цены, размер лота/контракта, котировочную конвенцию и курс конвертации**.

## 2. Как хранить цену: DECIMAL вместо FLOAT

В уроке 03 мы видели `DECIMAL(19,4)`. В нём цифры хранятся с заданной **десятичной** точностью. В `FLOAT` — с приближённой двоичной, поэтому некоторые привычные дроби вроде 0.1 не представляются точно.

```sql
USE TradingTraining;

SELECT TOP (5)
       trade_id, quantity, price,
       CAST(quantity AS DECIMAL(19,4)) * price AS example_notional
FROM dbo.trades
ORDER BY trade_id;
```

`CAST(quantity AS DECIMAL(19,4))` — «рассматривай значение как число с заданной десятичной точностью». Для реальных денежных расчётов нужно отдельно решить, **на каком этапе округлять** и до скольких знаков.

```sql
SELECT ROUND(CAST(12.3456 AS DECIMAL(19,4)), 2) AS rounded_example;
```

Результат — `12.3500` (в зависимости от способа отображения). `ROUND(..., 2)` округляет до двух цифр после точки. Это не заменяет правильное хранение данных.

## 3. Даты — не просто строки

У `trade_date` тип `DATE`. Для SQL Server это календарная дата, поэтому можно искать сделки за период:

```sql
SELECT trade_id, trade_date, price
FROM dbo.trades
WHERE trade_date >= '20240201'
  AND trade_date < '20240301'
ORDER BY trade_date, trade_id;
```

Мы попросили: **с 1 февраля включительно по 1 марта не включительно**. Такой диапазон удобен и для столбцов со временем: не нужно угадывать «последнюю миллисекунду дня».

Для даты и времени (которого в `trade_date` пока нет) в SQL Server существует `DATETIME2`.

## 4. Полезные функции дат

```sql
SELECT
    TRY_CONVERT(date, '31.12.2024', 104) AS parsed_date,
    DATEADD(day, 7, CONVERT(date, '20240109', 112)) AS plus_7_days,
    EOMONTH(CONVERT(date, '20240209', 112)) AS last_day_of_month;
```

- `TRY_CONVERT` пытается превратить текст в дату; если текст недопустим, даёт NULL.
- `104` — формат день.месяц.год; `112` — годмесяцдень.
- `DATEADD` добавляет интервал.
- `EOMONTH` возвращает конец месяца.

Сравни: `TRY_CONVERT(date, '31.02.2024', 104)` — это несуществующая дата, результат NULL.

## 5. Обычное среднее и средневзвешенное — не одно и то же

Представь две сделки: 1 акция по 100 и 9 акций по 200. **Простое среднее двух цен** = (100 + 200) / 2 = 150. Но **средняя цена одной купленной акции** = (1×100 + 9×200) / (1+9) = 190.

В нашей базе найдём оба показателя для одного инструмента `LKOH`:

```sql
SELECT
    AVG(price) AS simple_avg_price,
    SUM(CAST(quantity AS DECIMAL(19,4)) * price)
        / NULLIF(SUM(CAST(quantity AS DECIMAL(19,4))), 0)
        AS weighted_avg_price
FROM dbo.trades
WHERE instrument_id = 3;
```

Второй расчёт весит цену количеством. Это учебный аналог **VWAP** по выбранному набору сделок. В торговой отчётности выбор периода, BUY/SELL, режима и единиц измерения обязателен.

## 6. NULLIF защищает от деления на ноль

`NULLIF(x, 0)` вернёт NULL, если x равен нулю, иначе оставит x. В знаменателе это помогает вместо ошибки деления на ноль получить NULL — сигнал «рассчитать нельзя». Но нельзя автоматически считать такое NULL равным нулевой цене.

## 7. Как не перепутать число сделок и объём

```sql
SELECT
   side,
   COUNT(*) AS trade_count,
   SUM(quantity) AS quantity_total,
   SUM(commission) AS fees_total
FROM dbo.trades
WHERE instrument_id = 3
GROUP BY side;
```

Тут сразу три **разных** показателя: сколько сделок, сколько единиц инструмента и сколько комиссии. Даже когда в результате все числа, их смысл принципиально разный.
