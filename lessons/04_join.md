## Напоминание из урока 0: что мы делали руками

В уроке 0 вы вручную сопоставляли `trades.instrument_id` со строками `instruments`, глазами
находя нужный тикер. `JOIN` — это именно автоматизация того же самого действия, только
теперь SQLite делает сопоставление сам, для всех строк сразу.

## INNER JOIN по шагам

Задача: вывести сделки вместе с тикером инструмента, а не только числовым `instrument_id`.

```sql
SELECT
    t.trade_id,
    t.trade_date,
    i.ticker,
    t.side,
    t.quantity,
    t.price
FROM trades AS t
JOIN instruments AS i
    ON i.instrument_id = t.instrument_id
LIMIT 10;
```

Разберём этот запрос буквально по частям:

- `FROM trades AS t` — берём таблицу `trades` и даём ей короткий псевдоним `t`, чтобы не
  писать полное имя `trades` перед каждой колонкой.
- `JOIN instruments AS i` — присоединяем таблицу `instruments` с псевдонимом `i`. Без
  уточнения `JOIN` в SQLite означает `INNER JOIN` — это один и тот же оператор, просто слово
  `INNER` необязательно писать явно.
- `ON i.instrument_id = t.instrument_id` — это **условие соединения**: SQLite берёт каждую
  строку `trades` и ищет в `instruments` строку, где `instrument_id` совпадает. Именно это
  условие и есть автоматизированная версия того "ручного поиска глазами", который вы делали
  в уроке 0.
- В `SELECT` мы теперь можем обращаться к колонкам обеих таблиц одновременно:
  `t.trade_id`, `t.side` — из `trades`, `i.ticker` — из `instruments`.

**Важное правило INNER JOIN**: в результате останутся только те строки, для которых
совпадение по `ON` реально нашлось **в обеих** таблицах. Если бы существовала сделка со
ссылкой на несуществующий `instrument_id` — она полностью пропала бы из результата
`INNER JOIN` (но, как мы помним из урока 0, `FOREIGN KEY` вообще не позволяет такой сделке
попасть в базу — так что на практике это не наш случай).

## Соединяем сразу три таблицы

```sql
SELECT
    t.trade_id,
    t.trade_date,
    a.account_name,
    i.ticker,
    t.side,
    t.quantity,
    t.price,
    t.quantity * t.price AS turnover
FROM trades AS t
JOIN instruments AS i ON i.instrument_id = t.instrument_id
JOIN accounts    AS a ON a.account_id    = t.account_id
ORDER BY t.trade_date
LIMIT 10;
```

`JOIN` можно "цеплять" один за другим сколько угодно раз — каждый добавляет ещё одну
таблицу, у каждой свой `ON` со своим условием совпадения.

## LEFT JOIN: инструмент без сделок

Вспомните урок 1 — инструмент `TEST0` не имеет ни одной сделки. Проверим это через
`INNER JOIN`:

```sql
SELECT i.ticker, t.trade_id
FROM instruments AS i
JOIN trades AS t ON t.instrument_id = i.instrument_id
WHERE i.ticker = 'TEST0';
```

Результат — **пустой**. `TEST0` просто не появляется в результате `INNER JOIN`, потому что
для него нет ни одной подходящей строки в `trades` — а `INNER JOIN` показывает только те
строки, где совпадение реально нашлось.

Теперь то же самое через `LEFT JOIN`:

```sql
SELECT i.ticker, t.trade_id
FROM instruments AS i
LEFT JOIN trades AS t ON t.instrument_id = i.instrument_id
WHERE i.ticker = 'TEST0';
```

Результат — одна строка: `TEST0` и `trade_id = NULL`. `LEFT JOIN` (по-другому — `LEFT OUTER
JOIN`, слово `OUTER` необязательно) означает: **оставить все строки из "левой" таблицы**
(той, что указана в `FROM`, — здесь `instruments`), даже если для них не нашлось ни одной
подходящей строки в "правой" таблице (`trades`). Там, где совпадения нет, колонки правой
таблицы просто заполняются `NULL`.

Найдём **все** инструменты без единой сделки одним запросом:

```sql
SELECT i.instrument_id, i.ticker
FROM instruments AS i
LEFT JOIN trades AS t ON t.instrument_id = i.instrument_id
WHERE t.trade_id IS NULL;
```

Смысл: "возьми все инструменты, присоедини к ним сделки (если есть), и оставь только те, у
кого после присоединения `trade_id` оказался пустым" — то есть ни одной сделки не нашлось.

## LEFT JOIN: счёт без сделок

Ровно та же логика применима к `accounts` — вспомните `'ACC-DORMANT'` из урока 1:

```sql
SELECT a.account_id, a.account_name
FROM accounts AS a
LEFT JOIN trades AS t ON t.account_id = a.account_id
WHERE t.trade_id IS NULL;
```

Это вернёт `'ACC-DORMANT'` — счёт, который существует в справочнике `accounts`, но ни разу
не участвовал в сделках.

## INNER JOIN против LEFT JOIN — итоговое правило

| | Что делает |
|---|---|
| `INNER JOIN` | Оставляет только строки, у которых нашлось совпадение **в обеих** таблицах |
| `LEFT JOIN` | Оставляет **все** строки левой таблицы; если совпадения нет — колонки правой таблицы заполняются `NULL` |

Если бы мы построили отчёт "оборот по каждому инструменту" через `INNER JOIN`, `TEST0` в
нём вообще не появился бы — как будто такого инструмента не существует. Для отчёта "покажи
вообще все инструменты, включая те, по которым ещё не было ни одной сделки" обязательно
нужен `LEFT JOIN`.

## Коротко: RIGHT JOIN и FULL OUTER JOIN

`RIGHT JOIN` — зеркальная противоположность `LEFT JOIN`: сохраняет все строки **правой**
таблицы. `FULL OUTER JOIN` — сохраняет все строки **обеих** таблиц одновременно, заполняя
`NULL` там, где совпадения нет ни с одной из сторон. Современные версии SQLite (начиная с
3.39, у вас установлена более новая версия — уточните точный номер командой
`SELECT sqlite_version();`) поддерживают оба варианта. На практике `RIGHT JOIN` почти не
используют — почти любой `RIGHT JOIN` можно переписать как `LEFT JOIN`, просто поменяв
таблицы местами в `FROM`/`JOIN`, а это привычнее читать. Подробно эти два варианта в этом
курсе не разбираются — этого краткого знакомства достаточно, чтобы не растеряться, встретив
их в чужом коде.
