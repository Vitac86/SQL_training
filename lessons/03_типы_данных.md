# Урок 03. Типы данных: почему SQL Server различает числа, текст и даты

**Знакомо:** SELECT, WHERE, текст в кавычках и числовые условия. **Новое:** тип столбца, INT, BIGINT, VARCHAR, NVARCHAR, DECIMAL, DATE, NOT NULL.

## 1. Для чего нужен тип данных

В Excel ячейка иногда принимает почти всё. В SQL Server у каждого столбца задан **тип данных**: какие значения разрешено хранить.

Например:
- `trade_id` — целое число (номер сделки);
- `side` — текст BUY или SELL;
- `trade_date` — дата;
- `price` — число, у которого есть дробная часть.

Почему нельзя хранить всё текстом? Тогда сложнее надёжно считать суммы, сравнивать даты, проверять корректность. Даже число `100` в виде текста — это не то же самое, что числовое 100.

## 2. Посмотреть типы в интерфейсе SSMS

В Обозревателе объектов: `TradingTraining → Tables → dbo.trades → Columns / Столбцы`. Рядом с названиями будут типы вроде `int`, `date`, `bigint`, `decimal(19,4)`.

Посмотри `dbo.instruments` — для `name` используется `nvarchar`, потому что названия могут быть по-русски.

Тот же результат можно запросить через SQL, но пока **не нужно** запоминать системные таблицы. Достаточно GUI.

## 3. Самые нужные типы

**INT** — целое число, например 1 или 230. **BIGINT** — тоже целое, но допускает гораздо более крупные значения. Он используется для `quantity`.

**VARCHAR(32)** — текст до 32 символов (в рамках настроек кодировки SQL Server; для нашего набора тикеры латинские).

**NVARCHAR(200)** — текст в Unicode, подходит для кириллицы. При ручной вставке русской строки пишем `N'Название'`.

**DECIMAL(19,4)** — десятичное число с заданной точностью: всего до 19 цифр, из них 4 после запятой. Подходит, например, для цены, когда важна точная десятичная арифметика. `FLOAT` — приблизительное число, для финансовых расчётов с денежными значениями обычно не годится.

**DATE** — календарная дата без времени. Для реальных событий до секунды и доли секунды позже встретишь `DATETIME2`.

## 4. Убедимся на примерах

```sql
USE TradingTraining;

SELECT TOP (5)
    trade_id,       -- целое число
    trade_date,     -- дата
    quantity,       -- целое число
    price,          -- десятичное число
    side            -- текст
FROM dbo.trades
ORDER BY trade_id;
```

Попробуй простой расчёт:

```sql
SELECT 10 + 5 AS numeric_result;
SELECT '10' + '5' AS text_result;
```

Первый ответ — **15**, второй — **105** (SQL Server соединяет два текста). Один и тот же знак `+` ведёт себя по-разному в зависимости от типа.

## 5. Что означает NOT NULL

У столбца бывает дополнительное правило `NOT NULL` — «значение обязательно должно быть указано». Это **не тип**, а требование к данным.

В `trades` цена и количество обязательны. Смысл простой: запись вида «купить неизвестно сколько по неизвестной цене» нельзя считать корректной сделкой.

Пока только смотрим на это правило в структуре. В уроке 05 научимся создавать собственные правила и проверять, что бывает при ошибках.

## 6. Почему дата хранится как DATE

Строки с датой можно написать по-разному: `09.01.2024`, `2024-01-09`, `01/09/2024`. Но SQL Server должен знать, что это **дата**, чтобы сравнивать интервалы и упорядочивать события по календарю.

```sql
SELECT TOP (5) trade_id, trade_date
FROM dbo.trades
WHERE trade_date >= '20240201'
ORDER BY trade_date, trade_id;
```

`'20240201'` — формат YYYYMMDD, однозначно распознаваемый в SQL Server при сравнении с DATE. Работа с датами станет отдельной практикой в уроке 10.
