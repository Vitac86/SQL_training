# Урок 1. Устройство готовой базы trading_training.db

## Переход от lesson_00.db к trading_training.db

В уроке 0 вы своими руками собрали маленькую базу и разобрались, зачем нужны ключи и
ограничения. Теперь переходим к готовой учебной базе `trading_training.db` — она уже создана
из файлов в `data/` скриптом `01_create_database.py` и содержит правдоподобный набор
торговых данных.

Если вы хотите пересобрать базу заново с нуля (например, после того как что-то в ней
случайно испортили в предыдущих упражнениях):

```cmd
python 01_create_database.py
```

Это безопасно — скрипт полностью удаляет старый файл базы и создаёт его заново из CSV.

## Как подключиться

```cmd
sqlite3 trading_training.db
```

Полезные настройки вывода для удобного чтения результатов (наберите один раз в начале
сессии):

```sql
.headers on
.mode column
```

## Повторяем термины на реальных данных

```sql
.tables
```

Вы увидите пять таблиц: `instruments`, `accounts`, `trades`, `daily_prices`, `liquidity`.
Каждая из них — это то, что мы называли **таблицей** в уроке 0: набор однотипных записей.

```sql
.schema instruments
.schema trades
```

Посмотрите на вывод `.schema trades` и найдите глазами:

- `PRIMARY KEY` — какая колонка тут технический первичный ключ?
- `FOREIGN KEY` — на какие таблицы ссылается `trades`?
- `CHECK` — какие ограничения наложены на `side`, `quantity`, `price`, `commission`?
- `NOT NULL` — какие колонки обязательны?

Это те же самые концепции, что вы разобрали на маленьком примере в уроке 0 — просто теперь
на таблице с реальным (пусть и учебным) объёмом данных.

## Первый SELECT на торговых данных

```sql
SELECT * FROM instruments;
```

Каждая **строка** здесь — один конкретный финансовый инструмент. Каждая **колонка**
(`instrument_id`, `ticker`, `name`, `asset_class`, `currency`) — один атрибут, общий для
всех инструментов. Конкретное **значение**, например `'SBER'` в колонке `ticker` строки
Сбербанка — это данные на пересечении строки и колонки.

```sql
SELECT * FROM accounts;
```

Обратите внимание на счёт `'ACC-DORMANT'` — у него нет ни одной сделки. Запомните это имя,
оно понадобится в уроке 4 для разбора `LEFT JOIN`.

```sql
SELECT * FROM trades LIMIT 10;
```

`LIMIT 10` мы разберём подробно в следующем уроке — здесь он просто ограничивает вывод
первыми 10 строками, чтобы не листать все 230 сделок сразу.

## Самостоятельные задания

Решений здесь нет — они в `lessons/answers/01_answers.md`. Постарайтесь сначала решить сами.

1. Выведите все строки таблицы `daily_prices`, но только первые 5 строк.
2. Определите (посмотрев на `.schema instruments`), какая колонка в `instruments` защищена
   через `UNIQUE`, помимо `PRIMARY KEY`.
3. Найдите в таблице `instruments` инструмент с тикером `'TEST0'`. Запомните его
   `instrument_id` — в уроке 4 вы проверите, что у него нет ни одной сделки, через
   `LEFT JOIN`.
4. Выведите все строки таблицы `liquidity` за первую дату, которая встречается в этой
   таблице (пока можно не сортировать явно — просто посмотрите на `LIMIT`, отсортированный
   результат вы научитесь получать в уроке 2).
5. Посчитайте вручную (глазами, не запросом), сколько всего таблиц в базе и сколько из них
   ссылаются на `instruments` через `FOREIGN KEY` (подсказка: посмотрите `.schema` для
   каждой таблицы).
