# Урок 09. Подзапросы и CTE: строим запросы по шагам

**Знакомо:** SELECT/WHERE, агрегаты и JOIN. **Новое:** подзапрос — запрос внутри запроса; CTE — способ дать промежуточному результату понятное имя.

## 1. Возьмём задачу без SQL

Хочешь получить «сделки, у которых комиссия выше средней».

План на русском:
1. Посчитать **среднюю комиссию** по всем сделкам.
2. Найти сделки, где `commission` больше этого числа.

Второй шаг зависит от первого. Вместо ручного копирования среднего можно **вложить один SQL в другой**.

## 2. Первый подзапрос

```sql
USE TradingTraining;

SELECT trade_id, commission
FROM dbo.trades
WHERE commission > (
    SELECT AVG(commission)
    FROM dbo.trades
)
ORDER BY commission DESC;
```

Внутренний `SELECT AVG(...)` даёт одно число. Внешний `WHERE` сравнивает с ним каждую сделку.

Это и есть **подзапрос**. Здесь он должен возвращать **одно значение**, иначе выражение `commission > ( ... )` нельзя корректно выполнить.

## 3. Ещё пример: сравнение со средним по группе

Допустим, у каждого инструмента своя обычная цена. «Найди сделки дороже средней цены **своего** инструмента».

```sql
SELECT t.trade_id, t.instrument_id, t.price
FROM dbo.trades AS t
WHERE t.price > (
    SELECT AVG(t2.price)
    FROM dbo.trades AS t2
    WHERE t2.instrument_id = t.instrument_id
)
ORDER BY t.instrument_id, t.price DESC;
```

Заметь `t2.instrument_id = t.instrument_id`: внутренний запрос смотрит на номер инструмента **из текущей строки внешнего запроса**. Это называют **связанным (коррелированным) подзапросом**. Смысл простой: считаем среднюю цену именно для нужного инструмента.

## 4. EXISTS — «есть хотя бы одна строка?»

Задача: найти инструменты, которые хоть раз участвовали в сделке.

```sql
SELECT i.ticker
FROM dbo.instruments AS i
WHERE EXISTS (
    SELECT 1
    FROM dbo.trades AS t
    WHERE t.instrument_id = i.instrument_id
)
ORDER BY i.ticker;
```

`EXISTS` не нужно знать количество строк; ему достаточно ответа **«есть/нет»**.

Поменяй `EXISTS` на `NOT EXISTS` — получишь инструменты, по которым **нет ни одной сделки**, то есть `TEST0`.

## 5. CTE — дадим промежуточному запросу имя

Прежде мы писали всё сразу. Иногда проще выделить отдельный этап: «сначала посчитай сделки по счетам, потом покажи названия счетов».

```sql
WITH counts_by_account AS (
    SELECT account_id, COUNT(*) AS trade_count
    FROM dbo.trades
    GROUP BY account_id
)
SELECT a.account_name,
       COALESCE(c.trade_count, 0) AS trade_count
FROM dbo.accounts AS a
LEFT JOIN counts_by_account AS c
  ON c.account_id = a.account_id
ORDER BY a.account_name;
```

`WITH counts_by_account AS (...)` — назвали результат первого шага. После него обращаемся к `counts_by_account`, как если бы это была небольшая таблица. Это **CTE** (Common Table Expression), или «общее табличное выражение».

`COALESCE(c.trade_count, 0)` означает «если значение NULL, покажи 0». Поэтому `ACC-DORMANT` попадёт в результат с нулём.

**Важное отличие:** CTE **не создаёт постоянную таблицу**. Это именованный кусок **одного запроса**. Не рассчитывай, что результат CTE автоматически сохранится на диске.

## 6. Когда выбрать что

- Нужна информация **из двух таблиц** в одной строке — обычно JOIN.
- Нужно проверить, есть ли хотя бы одна запись — EXISTS/NOT EXISTS.
- Нужно посчитать одно число, чтобы сравнивать с ним строки — скалярный подзапрос.
- Запрос трудно читать целиком — разбей на понятные этапы с CTE.

## Задания

1. Найди сделки с `price` выше среднего по всей таблице.
2. Найди счета, у которых **нет сделок**, через NOT EXISTS.
3. Через CTE посчитай суммарную комиссию по каждому счёту и покажи названия счетов (включая пустой).
4. Объясни, чем CTE отличается от таблицы, которую ты создавал через CREATE TABLE в уроке 05.

**Самопроверка:** для второго задания ожидается `ACC-DORMANT`; CTE называет **промежуточный результат одного запроса**, а CREATE TABLE создаёт **хранимую таблицу**.
