# Урок 10. Транзакции и ACID

**Цель:** управлять несколькими изменениями как одной операцией.

## ACID — четыре гарантии и ограничения

- **Atomicity:** все изменения транзакции фиксируются целиком или откатываются.
- **Consistency:** ограничения сохраняются, если они корректно определены; SQL Server не может сам гарантировать все бизнес-инварианты без модели и логики.
- **Isolation:** конкурентные транзакции влияют друг на друга согласно уровню изоляции; это **не обязательно** полная сериализация.
- **Durability:** зафиксированные изменения рассчитаны на сохранение после сбоя согласно механизму журналирования и гарантиям инфраструктуры.

Транзакции важны для примеров «уменьшить доступный лимит и записать поручение», «изменить два взаимосвязанных справочника», «согласованно принять пакет».

## BEGIN TRAN, COMMIT, ROLLBACK

```sql
USE TradingTraining;
BEGIN TRANSACTION;

UPDATE dbo.accounts
SET risk_limit_rub = risk_limit_rub + 1000
WHERE account_id = 6;

SELECT risk_limit_rub FROM dbo.accounts WHERE account_id = 6;
ROLLBACK TRANSACTION;

SELECT risk_limit_rub FROM dbo.accounts WHERE account_id = 6;
```

`ROLLBACK` отменяет незакоммиченные изменения текущей транзакции. После `COMMIT` обычным `ROLLBACK` их уже не вернуть. Для реальных данных нужны backups/восстановление и аудит.

## Защита при ошибках

```sql
SET XACT_ABORT ON;
BEGIN TRY
    BEGIN TRANSACTION;

    UPDATE dbo.accounts
    SET risk_limit_rub = risk_limit_rub + 1
    WHERE account_id = 6;

    -- Симулируем бизнес-ошибку:
    THROW 51010, N'Демо: не фиксируем изменение', 1;

    COMMIT TRANSACTION;  -- сюда не дойдём
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0 ROLLBACK TRANSACTION;
    SELECT ERROR_NUMBER() AS error_number,
           ERROR_MESSAGE() AS error_message;
END CATCH;
```

`XACT_ABORT ON` откатывает транзакцию при многих ошибках времени выполнения (есть нюансы). `XACT_STATE()` различает отсутствие транзакции, активную и «нефиксируемую» (uncommittable). **TRY/CATCH не ловит абсолютно все ошибки**: например, некоторые ошибки компиляции на том же уровне, разрывы соединения и административное завершение.

## Вложенные транзакции и SAVE TRAN

`@@TRANCOUNT` показывает вложенность `BEGIN TRAN`, но SQL Server не делает независимые вложенные фиксируемые транзакции. Внутренний `COMMIT` лишь уменьшает счётчик; долговременная фиксация требует внешнего COMMIT. `SAVE TRAN savepoint_name` устанавливает точку частичного отката в допустимом состоянии транзакции.
