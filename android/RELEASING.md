# Подписанные обновления SQL Trainer через GitHub Releases

В приложении с версии **0.5.0** есть кнопка обновления (иконка загрузки/обновления в верхней панели). Она проверяет публичный GitHub API `releases/latest`, сравнивает версии и при согласии пользователя скачивает APK с GitHub Releases. Установка выполняется **системным установщиком Android**, с подтверждением пользователя.

## Почему нужен GitHub Releases

Артефакты обычного CI-воркфлоу `Android build` хранятся ограниченное время и могут требовать входа в GitHub. Приложение использует публичные **Releases** и ищет APK с точным именем `sql-trainer.apk`. Никакие GitHub-токены в Android-приложение не вшиваются.

**Сейчас первая опубликованная версия отсутствует.** До публикации первого Release кнопка покажет ссылку на сборки GitHub Actions.

## Однократная настройка постоянного ключа

Важное условие Android: все версии APK с одним `applicationId`, устанавливаемые друг поверх друга, должны иметь одинаковую криптографическую подпись. Старые debug APK из GitHub Actions могли быть подписаны разными временными ключами. Стабильный релизный ключ нужен **для всех будущих обновлений**.

1. На своём Windows-компьютере с установленным JDK открой PowerShell и создай закрытый ключ (ввод пароля интерактивно):

   ```powershell
   $key = "$env:USERPROFILE\sqltrainer-signing.jks"
   keytool -genkeypair -v -keystore $key -alias sqltrainer -keyalg RSA -keysize 3072 -validity 10000 -storetype PKCS12
   ```

   Используй **один и тот же пароль хранилища и ключа**. Сохрани JKS и пароль в своём надёжном резервном хранилище. Потеря ключа не позволит выпускать совместимые обновления.

2. Зайди в [настройки секретов репозитория](https://github.com/Vitac86/SQL_training/settings/secrets/actions) → **New repository secret**. Создай:
   - `ANDROID_SIGNING_KEYSTORE_B64`: содержимое JKS в Base64. Чтобы скопировать значение в буфер обмена без вывода в консоль:
   
     ```powershell
     [Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\sqltrainer-signing.jks")) | Set-Clipboard
     ```
   
   - `ANDROID_SIGNING_PASSWORD`: пароль хранилища JKS и ключа.

   Не отправляй пароль, Base64 или закрытый ключ в чат, Issues и коммиты. **Base64 — не шифрование.**

3. После появления коммита версии 0.5.0 в `main` создай и отправь тег:

   ```powershell
   cd C:\SQL
   git pull origin main
   git tag v0.5.0
   git push origin v0.5.0
   ```

4. Workflow [Android signed GitHub Release](https://github.com/Vitac86/SQL_training/actions/workflows/android-release.yml) проверит тег, прогонит тесты, соберёт **подписанный APK**, проверит его подпись и создаст Release с файлом `sql-trainer.apk` и `SHA256SUMS`.

При недостаточных правах `GITHUB_TOKEN` для публикации: Settings → Actions → General → Workflow permissions → **Read and write permissions** (если доступно). В самом workflow запрошено `contents: write`.

## Следующие версии

При изменении приложения увеличь `versionCode` и `versionName` в `android/app/build.gradle.kts`, например `0.5.1` и `7`. Важно: тег релиза обязан соответствовать `versionName`, например `v0.5.1`. Опубликуй тег — workflow соберёт APK **тем же сохранённым ключом**.

## Как работает кнопка

- При открытии окна отправляется одиночный запрос `GET /repos/Vitac86/SQL_training/releases/latest` к GitHub.
- Если новой версии нет — показывается уведомление. Если Releases ещё пуст — предлагается открыть Actions.
- Если версия новая, можно просмотреть заметки о выпуске и нажать «Скачать APK».
- Android DownloadManager выполняет загрузку. При доступной SHA-256 из GitHub API проверяется контрольная сумма.
- «Установить» запускает системный установщик; при необходимости Android предложит разрешить установку из SQL Trainer.
- Если закрыть диалог во время загрузки, скачивание продолжается; при повторном открытии окно найдёт загрузку.

**Установка не происходит скрытно и без подтверждения.** Само обучение работает полностью офлайн, сетевое подключение нужно только для функции обновления.

## Миграция с предыдущих debug APK

Первая установка подписанного релиза поверх ранее установленного debug APK может быть заблокирована Android из-за несовпадения сертификатов. Тогда обычно требуется удалить старую версию и установить релиз; **при удалении приложения локальный прогресс и сохранённые SQL могут быть потеряны**. Обязательно сохрани важные SQL-запросы заранее. После перехода на постоянный релизный ключ дальнейшие обновления должны устанавливаться без удаления приложения.

Не публикуй APK с другим ключом под тем же `applicationId` в будущем.
